# Flaky-test ledger

Every test that failed on one machine, or under load, and passed on another machine or on a repeat. Use it to tell a known
flake from a new defect fast. Newest knowledge wins: update an entry when its fix merges or it is seen again.

Status words:

- **Fixed**: the cause is known and the fix is merged (or the fault was in an unmerged branch and that branch is fixed).
- **Watching**: seen once or twice, cause not proven, or fixed but not yet seen staying green for long.
- **Open**: the cause is known or suspected, but no fix is merged yet.

"Under load" means a full suite with other test runs on the same box. Counts are failures out of runs: "17/100" is 17 failing
runs out of 100. The Linux box is Linux on Arm (arm64), headless Chrome; Pythons 3.9.25 and 3.15.2 unless stated.
Item numbers like "plan item #100" are on the planning board; "PR #117" is a pull request on this repo.

## What to do when a test fails once

Do not call it a defect yet. When a file fails in a full run, the runner repeats it alone; if it passes alone, the run
still counts as a pass, and the file is logged (`python3 dev/run_tests.py --flaky` lists those files, most often first).
First, repeat the failing test alone yourself (`python3 dev/run_tests.py <file>`). Second, run it again with the suite, or
under load (`--repeat 6 --stress 8`), to see how often it fails. Third, compare the message with this ledger: the same test
failing the same way is a known flake, so add the run to its counts and carry on. Only when it fails alone every time, or
fails in a way this ledger does not describe, call it a defect: find the cause, fix the test or the product, and add a row
here with before and after counts.
