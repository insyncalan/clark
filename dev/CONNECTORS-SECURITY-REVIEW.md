# ask clark connectors: security review (Row 1306)

Scope: the connectors that ask clark may read when the person turns them on in Settings (Microsoft 365: Mail, Calendar, Teams, SharePoint and OneDrive; Todoist's switch is hidden, see finding F3). Read-only review of the code on `origin/main` (c6ae7ff20) plus the fixes in this change. Nothing was run against a real connector: this box is Linux and the command only runs on a Mac (`ask_claude.py` `command()`), so every statement marked "code and fake command" is proved by tests with a faked command, and every statement marked "not verified" needs a Mac with Microsoft 365 connected.

## Findings fixed in this change (each with a test)

- **F1. The request did not say tool results are data.** `ask.RULES` rule 1 treats only passages as data and rule 2 says "You have no tools". In a connector run the model has tools and their results are text anyone can write. Fix: a fixed note in front of the request of a connector run only (`ask_claude.py` `CONNECTOR_NOTE`, applied in `answer()`); a run with no connector is byte-identical to before. Test: `tests/test_ask_connector_data_note.py`.
- **F2. A change after a connector run did not need the separate Confirm.** `AskService.hold` marked a reply `from_source` only when a folder passage was sent, so a change suggested after the model read a mail or a Teams chat could be applied with Apply alone. The ticket (test 5) wants the extra tick. Fix: `hold(..., from_connector)` marks the reply when the run had a connector in it (`ask_service.py`). Test: `tests/test_ask_connector_change_gate.py`; the mutant in `tests/test_ask_change_route.py` takes the new argument.
- **F7. The shown words said the opposite of what the code now does.** The first-run card and Help said ask clark "never reads your mail, Teams or calendars". With a connector On that is false. The ticket's step 3 had not been done (the ticket says the prototype already has the sentence; the plan repo's prototype and mock-ups do not, checked by search). Changed in `askWords.js` and `helpContent.json` (2 places) to the decided sentence. Test: `tests/test_ask_connector_words_1306.py`, and `tests/test_ask_first_run_1292.py` updated.

## Findings not fixed here

- **F3. Todoist can be turned On and is never read.** `READ_TOOLS` has no Todoist table, so a Todoist switch that is On leaves the call locked down (pinned by `test_ask_connector_wiring` `test_todoist_alone_has_no_allow_table_so_it_is_exactly_today`). The person sees On and nothing is used or said. Todoist read tool names were never probed. Ruling (recorded on the ticket, 20-11): the switch is hidden (`HIDDEN_CONNECTORS`) until Todoist's read-only tool names are probed and allow-listed; reading it is TD v1.4.
- **F4. `read_resource` is no longer allowed under SharePoint and OneDrive (fixed in code, 20-11).** It is a general resource reader of the Microsoft 365 server, so it is out of `READ_TOOLS` and out of the screen's `ALLOWED_TOOLS`, and denied by name whenever the server is On (`NEVER_ALLOWED`). With only SharePoint On, a call to it with a mail address is refused by the screen and the run check, and it is not in the allow arguments. Every other SharePoint read tool still works. Test: `tests/test_ask_connector_f45_1306.py` (fake server). A live probe on a Mac is a v1.4 row (row 1422).
- **F5. A claude.ai server that is not in `KNOWN_SERVERS` is denied before any call (fixed in code, 20-11).** Every server in the fresh discovery that is not On is denied whole by prefix, known or not; a listed server whose name cannot be turned into a prefix (a hidden character, an apostrophe, a leading dash) ends the connector run before it starts (`build_call` refuses, the call is the locked-down one). Test: `tests/test_ask_connector_f45_1306.py` (a fake server outside the list; its handler is never reached). A server that appears after the discovery: the call keeps the server names its arguments were built from (`Call.servers`); after the run a fresh list is read (`server_appeared`), and a new name, or a list that cannot be read, refuses the whole answer (nothing is shown). A deferred tool that is neither allowed nor denied (a new tool of the On server, or a tool of a late server): the command has no allow for it, ToolSearch for it and a call to it are refused by the stream check, so the run is refused (tests `F5LateServer`). A live probe on a Mac is a v1.4 row (row 1423).
- **F6. A DRAFT line from a connector run is marked (built, 20-11).** The draft stays a card the person adds; nothing is in the report until then, and no extra tick (ruling 20-11). The server hands the names of the parts read (`via`, never what they returned) and the card and the draft sheet say "Written using your <parts>. Read it before you apply it." The words are approved. Test: `tests/test_ask_connector_draft_via.py`.

## Decision

Connectors may ship as built (off by default, read only, per project turn-off, change gate) once F1, F2 and F7 are merged. F4 and F5 (the two that could let a hostile mail reach something the person did not turn On) are fixed in code and pinned by tests with a fake server; their live Mac probes are v1.4 rows (rows 1422 and 1423). F3 and F6 and the other Mac checks above stay as written.
