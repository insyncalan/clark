# Hand-check sheet for clark 1.1.0, Windows (Docker route)

Written for the person with a real Windows laptop. Windows runs clark through Docker, not a native build (item 627). Item 623 is the Windows spike; its title says v.0.10, but its done-when is checked on this sheet. Assume Docker is already running, in Linux containers mode. Only what a test cannot decide; a failed line holds back the Windows zip only, never the Mac release. Tick each line; write what you saw where it fails.

**Sample data only.** Use the fictional demo projects, not real client data.

Each line ends with the v1.1 item id it checks.

## Windows checks

- [ ] Extract the zip with Windows' own "Extract all" into Downloads. The clark folder is complete and nothing is left half unzipped, including the files with long names. (#624)
- [ ] Start clark with the typed commands in PowerShell. The company's PowerShell rules allow them, and clark is reachable when you open http://localhost:8766 yourself in Chrome or Edge. (#623)
- [ ] Start clark with the typed commands in Command Prompt. The company's Command Prompt rules allow them, and clark is reachable when you open http://localhost:8766 yourself in Chrome or Edge. (#623)
- [ ] Type a data-folder path inside OneDrive with spaces in it, in the Windows form (C:\Users\<you>\OneDrive - Name\clark). clark does not accept that data folder and says it is in OneDrive. (#623, #635)
- [ ] Start clark with the typed commands in a shell where USERPROFILE is not set (for example Git Bash or a WSL shell), and with no data folder chosen. The data folder must not become /clark-data at the root of the drive or of Docker's own disk: clark either stops with a message, or keeps the data in a folder you can find in your user folder. Write what happened. (#629)
- [ ] Add a project, stop clark, start it again. The data is still there after the restart. (#632, #623)
- [ ] Make a backup. In PowerShell, in the clark folder, type `$env:CLARK_COPY_DIR = "D:\Backups"` (your own Windows backup folder), then start clark with `docker compose -f docker/compose.yaml -f docker/compose.windows.yaml -f docker/compose.copy.yaml up -d`, and in Settings type /backups-out as the copy folder. Make a backup: the finished backup shows in your Windows backup folder (clark copies it there on its own, do not copy it by hand). To restore, type the same -f files with `down`, then `docker compose -f docker/compose.yaml -f docker/compose.windows.yaml -f docker/compose.copy.yaml run --rm clark python3 -m clark restore --data /data --from /backups-out NAME` (NAME is the backup's name in the folder), then the same files with `up -d`. The backup restores and the data matches. This line can only pass once item 634 and item 629 are merged: until then docker/compose.copy.yaml (which holds the /backups-out mount) and docker/compose.windows.yaml are not in the download. (#634, #629)
- [ ] Mark which way you started clark: the Mac starter (bash docker/start.command, only if this laptop has bash, for example Git Bash), or the typed docker compose commands in PowerShell. With the Mac starter: with Chrome installed, clark opens in Chrome; with only Edge, in Edge. In each, the browser opens clark as a normal page in an ordinary window (not an app window). The starter itself says nothing about the browser; the doctor does: on a Mac, in the clark folder, type `bash clark.command --check`, and its browser line says which browser is there, so clark opens in it (Google Chrome, or Microsoft Edge when Chrome is not installed), the same one the page opened in. With the typed docker compose commands (the Windows way): clark opens nothing, so open http://localhost:8766 yourself in Chrome or Edge; the page loads in an ordinary window. Installing it as a web app stays your choice and is not checked here. (#636)
- [ ] On a Mac, start clark with the Mac starter (bash docker/start.command) from a Terminal window, then close that Terminal window while clark's browser window is open. The browser window stays open and clark keeps working (the starter starts the browser in the background; closing the Terminal must not close it). Then start again and see clark's window open once. (#636)
- [ ] Stop clark and reload the page. The offline page shows and does not show an error trace. (#632)
- [ ] LAN check: from another device on the same network, open the laptop's address on the clark port. clark does not answer. (#638, #635)
- [ ] Save a file. The saved-file wording says where it was saved in plain words, in the Windows path form. (#625, #629)
- [ ] Read a date shown in clark, such as a new item's created date. The date is the day it is on the laptop, in the laptop's own time zone. (#631)
- [ ] Open ask clark. It says ask clark is not available on Windows yet. (#629)

## Updating on Docker (item 633)

Done on the same Windows laptop. Each line is checked against docker/UPDATE-windows.txt.

| Id | Check | You should see |
|----|-------|----------------|
| 633.1 | Start the old clark folder, add a change, stop it, rename the old clark folder to clark-old, unzip the new download into the folder that held it (if you use Extract All, change the folder it shows to that folder first), start the new clark folder with the up command from docker/UPDATE-windows.txt | The change is still there. |
| 633.2 | When the new clark has a newer data version, start the old folder again | The words "start from the newer clark folder. Nothing was changed." appear in docker compose logs, and docker ps shows the container idle and unhealthy. |
| 633.3 | After the update, open clark-data\backups | A file ending in -migrate.db is there. |

| 633.5 | Type the Get-FileHash line on the Windows zip | The number equals the one on the release page. |
| 633.6 | Stop the new clark while the data is newer than it, and look at the container under Docker Desktop | The container holds idle (the sh -c command in docker/compose.yaml runs inside the Linux container). |
