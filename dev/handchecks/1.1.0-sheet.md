# Hand-check sheet for clark 1.1.0, Windows (Docker route)

Written for the person with a real Windows laptop. Windows runs clark through Docker, not a native build (item 627). Assume Docker is already running, in Linux containers mode. Only what a test cannot decide; hand checks never hold up a release. Tick each line; write what you saw where it fails.

**Sample data only.** Use the fictional demo projects, not real client data.

Each line ends with the v1.1 item id it checks.

## Windows checks

- [ ] Extract the zip with Windows' own "Extract all" into Downloads. The clark folder is complete and nothing is left half-extracted. (#624)
- [ ] Start clark with the typed commands in PowerShell. clark opens in the browser. (#623, #625)
- [ ] Start clark with the typed commands in Command Prompt. clark opens in the browser. (#623, #625)
- [ ] Unzip into a OneDrive path with spaces in it and start clark. clark refuses the path and says so. (#635)
- [ ] Add a project, stop clark, start it again. The data is still there after the restart. (#632, #635)
- [ ] Make a backup, copy it to the Windows folder, then restore it with the typed commands. The backup restores and the data matches. (#634)
- [ ] Open clark in Edge as an app window, then in Chrome as an app window. Both open clark. (#636)
- [ ] Stop clark and reload the page. The offline page shows and does not show an error trace. (#632)
- [ ] LAN check: from another device on the same network, open the laptop's address on the clark port. clark does not answer. (#635, #638)
- [ ] Save a file and read a date shown in clark. The date is in the Dubai zone and the saved-file wording and Windows path look right. (#625, #629)
- [ ] Release path: the Windows zip is the one that was published for download, and the CI jobs for Windows ran. (#626, #627, #630)
