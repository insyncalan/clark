# Hand-check sheet for clark 1.3.7

Written for the person who looks at the screens after the release. One line for each thing a person can see that changed; only what a test cannot decide. Hand checks never hold up a release.

**Sample data only.** The fictional demo projects. Run `bash clark.command --demo` in the unzipped clark folder. Laptop only: Chrome at 1400 px wide, then again at 900 px. Light and dark where a line says so. Do not press Export, Save or Publish on real data.

Each row: PR, what to check by hand, and what you should see. Tick each line; write what you saw where it fails.

Screens changed since 1.3.6: Dashboard At a glance (Edit), Text and Image Side by Side, Milestones switch buttons, the project title bar, ask clark (panel and Settings). Every line is taken from the merged PR text and the code it changed; words in quotes are the words on the screen.

(origin/main head 283fe9bfa; built from the first-parent merges since v1.3.6. Lines below that a test cannot decide; hand checks never hold up a release.)

## Dashboard: At a glance, Edit (rows 1336, 1341: PR 1985)

- [ ] In Edit, on the Dashboard, open a section built from the At a glance template. You should see each tile (not Project health) with three small controls at its top right: a grip, an eye and a bin, and the tile's words (label, note) not running under them. Check at 1400 and 900.
- [ ] Press the bin on one counting tile (for example Overdue actions). You should see the tile leave the strip and a toast "Deleted: Overdue actions" with Undo. Press Undo: the tile comes back where it was.
- [ ] After a bin press, press "Add a tile". You should see the deleted tile offered again and, once chosen, back on the strip. A tile you made yourself keeps its pencil and its own controls.
- [ ] Look at the line under the tiles. You should see "Drag a tile to move it, or hold Alt and press an arrow key. The eye hides a tile from the published page; the bin deletes it. Add a tile brings it back."
- [ ] Look at the tiles side by side at 1400. You should see an even 12 px gap between them, each tile the same width, and the bin dark at rest and red when the mouse is over it.
- [ ] Give Project health a long reason (or use a demo project that has one). You should see the reason wrap under the health pill at the tile's inner width, not squeezed beside it, and a long word breaks inside the tile. Look in Edit and in View, at 1400 and 900.
- [ ] Publish a test file with one tile bin-deleted. You should see that tile missing from the file, as it is when hidden with the eye.

## Project title bar (row 1341: PR 1985)

- [ ] Open a project with a very long name. On the Dashboard, Work items, Milestones, Use cases and Gantt pages, and on Settings, look at the bar at the top at 1400 and again at 900. You should see the name on one line, cut with "…" at the end, the line under it ("Weekly report") and the page tabs inside the bar, and no sideways scroll.
- [ ] Hold the mouse over the cut name. You should see the full project name in the tip.

## Milestones: the five switch buttons (row 1315: PRs 2113, 2187)

- [ ] Open the Milestones page at 1400 and 900. Look at the Timeline / Calendar switch, and (in the Calendar) the Week / Month / Quarter switch. You should see a thin grey frame round each, a thin grey line between the halves, buttons 28 px high with the same side room, and the chosen half navy with white text.
- [ ] Look at the half that is not chosen in each switch. You should see dark grey text that reads clearly on white, in light and in dark. Click the other half: the colours swap.
- [ ] Look at the dashed add-milestone button and the Plan / Movement switch. You should see them as before (nothing moved).

## Text and Image Side by Side (row 1232: PRs 2176, 2177, 2179, 2180, 2181, 2185)

- [ ] Open the section picker in Edit and look at Text. You should see the card named "Text and Image Side by Side" (not "Text and image") with the same description, "Full or half". Open Help, the section list: the same name.
- [ ] Add a Text and Image Side by Side section, full width, with no image. You should see a "Heading" box (optional), a "Text" editor and an area to choose an image ("Choose an image", "or drop one here"). Until something is added the line "Add some words, an image or both. Until then this section stays out of the published page." shows.
- [ ] Add a picture. You should see it beside the words, the words and the picture the same height, a round focus dot on the picture, the icon bar "Image and layout tools" docked under it, and a note "N × N px file. Made smaller for print to 3,000 px at most (300 dpi). The published page carries only the part you see." Look at 1400 and 900.
- [ ] Use the icon bar: Shape (Fill the height of the text, 4:3, square, Whole image), Where the image sits (left or right, then Swap image and text), Width of the image (a third, a half, two thirds), then Crop, Reset framing, Replace, Remove. Each press changes the picture at once; the pressed button has a blue ring; hovering a button fills it pale; Remove goes red on hover. Each change is one Undo.
- [ ] Drag the focus dot over a tall picture. You should see the part of the picture that stays in view follow the dot. At 900 the section stacks: the picture above the words when it is on the left, below when it is on the right.
- [ ] Put the same section at half width. You should see the bar offer top or bottom ("Image on top", "Image underneath") and a wide 16:9 shape instead of the three widths.
- [ ] Look at the "Describe the image" box with a picture and no description. You should see the red line "No description yet." and the box edge red; once you type, both go.
- [ ] Open View. You should see the heading above the picture and words, the picture in the shape you chose, and the picture on the side you chose (stacked at 900); half width shows picture above or below the words. Publish a test file and open it: the same.
- [ ] Export the Word report (sample data). Open it in Word and look at the print preview. You should see the section name, the heading you typed, the picture as framed with its caption under it in small grey type (a small picture centred), and the words; the picture first when it is on the left, after the words otherwise.

## ask clark: panel (rows 1293, 1294: PRs 2188, 2164)

These need ask clark connected on the laptop. Use only the demo project.

- [ ] Ask a question and press Stop at once. You should see the line "Stopped. Nothing was changed." and no answer appearing afterwards, even a moment later.
- [ ] Open the panel and look at the paperclip. You should see it with the hint "Add a file" (not "Add a file or picture"), and the file chooser offering text, Markdown and CSV files only.
- [ ] In Settings, ask clark, turn Files off for all projects (see the Settings lines below), then reopen the panel. You should see no paperclip, and dropping a file on the panel does nothing.
- [ ] Ask a question whose passages hold hidden characters (for example a text file in a source folder with a zero-width space pasted in). You should see, in the notes under the answer, a line for that passage: "<passage>: this passage has N hidden character(s)."

## ask clark: Settings (rows 1294, 1371: PRs 2174, 2175)

- [ ] Open Settings, ask clark, a project's tab, at 1400 and 900. You should see the cards in this order: Slash commands, Files, Chats, Usage last. The Files card is titled "Files in <project code>" and has one switch.
- [ ] On the All projects tab you should see a Files card with the line "Files: text, Markdown and CSV (5 files of 10 MB, for that question only). A project can turn these off for itself." and a switch. Turn it off and then press Undo: each press gives a change and Undo restores it.
- [ ] Add a source folder and watch the quiet line under it. You should see "Indexing… N%" counting up, then "100% indexed"; with unreadable files "100% indexed. N files could not be read" followed by a "(why)" link that opens a plain list (file name, then reason). A folder with nothing to read says "No files to index", never "100% indexed".
