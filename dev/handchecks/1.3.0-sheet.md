# Hand-check sheet for clark 1.3.0

Written for the person who looks at the screens after the release. One line for each thing a person can see that changed; only what a test cannot decide. Hand checks never hold up a release.

**Sample data only.** The fictional demo projects. Run `bash clark.command --demo` in the unzipped clark folder. Laptop only: Chrome at 1400 px wide, then again at 900 px. Light and dark where a line says so. Do not press Export, Save or Publish on real data.

Each row: what to check by hand, and what you should see. Tick each line; write what you saw where it fails. Every line is taken from the merged PR text.

Screens changed since 1.2.0: Work items list priority and filter chips, the Group by, Move to and Add menus, the Dashboard row menu, the Settings menu, the report header, use case rows.

## Work items list (rows 1282, 1290)

- [ ] Open the Priority cell of a risk or an issue in the Work items list. You should see the Impact by Likelihood grid, as in the peek. The arrow keys move and stop at the four edges; Enter or Space picks; Esc or a click outside closes it with nothing changed. An action or a decision still opens a plain list.
- [ ] Look at the filter chips. You should see rounded rectangles in the loaded brand colour with a remove cross; plain-word chips stay grey. Check light and dark.

## Menus (rows 1273, 1296)

- [ ] Open Group by in the View menu. You should see its head in capitals, a tick before the icon and a panel wide enough for the words.
- [ ] On a board, open Move to on a card in the right-most column. You should see the panel open to the left, inside the window, with the card's own column ticked and not clickable.
- [ ] Look at Add milestone, Add project and Add use case. You should see the dashed border of the Add opener on Work items.
- [ ] Right-click a risk row on the Dashboard. You should see the Work items row menu; the menu key and Shift+F10 open it too; Escape puts focus back on the id button.

## Settings and header (rows 1280, 1239)

- [ ] Open the Settings menu. You should see group headings in small muted capitals that you cannot click, and 32 px page rows with a hover fill; the open page is marked. Check light and dark.
- [ ] Give a project a very long name (sample data) and look at the editor header and a published report. You should see the name wrap, never cut with an ellipsis; the bar grows to hold it. Check 1400 and 900.

## Use cases (row 1277)

- [ ] On a use case page, change the window size and drag a row. You should see the rows box refit, and a drag end when you let go.

Not checked by anyone (taken from the PR texts): macOS; screen reader; widths other than 1400 and 900.
