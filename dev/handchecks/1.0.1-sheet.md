Written for the person who looks at the screens after the release. Only what a test cannot decide; everything else is covered by `tests/test_v101.py`. Hand checks never hold up a release.

**Sample data only.** The fictional demo projects. Run `python3 -m clark --demo --open` in the top folder of the release. Laptop only: Chrome at 1400 px wide, then again at 900 px. Light and dark where a line says so.

Each row: id, what to check by hand, what you should see, and how it is covered. Tick each line; write what you saw where it fails.

## For the Head at the cut

- **Version.** The cut commit sets `__version__ = "1.0.1"`, so the cut checks in `tests/test_v101.py` run.
- **Data layout.** 1.0.0 reads layout 15 (SCHEMA_AT_1_0_0 in `tests/test_v101.py`). The notes carry the layout paragraph for the use case flag (#709, PR 673 backend). At the cut SCHEMA_VERSION must be 16: `test_the_layout_step_is_in_at_the_cut` fails otherwise. If #709 does not make the cut, delete the layout paragraph and the Read this first heading from the notes, and set SCHEMA_AT_1_0_1 handling in the test back to "layout unchanged".
- **PR numbers.** Each row names its PR as "PR NNN" next to the item number; the two numberings overlap (PR 664 is item #696, PR 661 is item #664). Item 709's backend is PR 673 (its page parts have no PR yet). Items 662, 672, 687, 698, 713, 716, 717, 720 have no open PR.
- **DRAFT lines.** Each notes line ending DRAFT is not merged yet: remove the line if its work misses the cut, or remove the DRAFT words and the comment under it once merged, and move its row to COVERED.
- **Older tests.** `tests/test_v100.py` and `tests/test_v0110.py` assert that their notes carry the layout paragraph exactly when SCHEMA_VERSION is not 15: once the #709 backend merges they fail unless their schema gate is moved (they describe 1.0.0 and 0.11.0, which read layout 15).
- **Title.** The 1.0.1 title carries (Beta), and RELEASING.md steps 2 and 8 read as for the earlier releases.
