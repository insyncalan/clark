# Hand-check sheet for clark 1.3.2

Written for the person who looks at the screens after the release. One line for each thing a person can see that changed; only what a test cannot decide. Hand checks never hold up a release.

**Sample data only.** The fictional demo projects. Run `bash clark.command --demo` in the unzipped clark folder. Laptop only: Chrome at 1400 px wide, then again at 900 px. Light and dark where a line says so. Do not press Export, Save or Publish on real data.

Each row: what to check by hand, and what you should see. Tick each line; write what you saw where it fails. Every line is taken from the merged PR text.

Screens changed since 1.3.1: the Classic Theme (Dashboard, Work items, Milestones, Use cases, Settings), the Work items list Edit, ask clark (panel, Draft sheet, slash menu, quick bar, files), Settings (ask clark tabs, Connectors), At a glance, the published file, the Word file.

## Classic, all pages (rows 1310, 1311, 1319, 1320)

- [ ] In Settings, pick Classic and reload. You should see a soft light-to-lighter page background in light and in dark, headings a little lighter in weight, plain breadcrumbs (not in capitals), and rounded corners on buttons and segments.
- [ ] Look at a chosen segment (for example the Milestones scale). You should see navy with white text. In dark it has a thin grey edge you can see.
- [ ] Look at a main button (for example Apply or Done). You should see an aqua pill with a soft glow, lifting a little on hover and sinking when pressed. Check light and dark.
- [ ] Open the Dashboard of a project with a Work items list. You should see the View | Edit pill at the top, and pressing V and E switches mode. With the Welcome card showing, the pill is still there and the focus stays where it was.

## Classic Dashboard (rows 1260, 1310, 1311, 1313, 1318)

- [ ] Open the Dashboard. You should see no outer white card, and the 1st, 3rd, 5th and 7th sections on a white band, in light and dark.
- [ ] At 1400 px you should see a Contents list on the left, with the active entry marked by a 2 px rule, and no rail on the right. Click an entry: the page jumps to it. At 900 px the Contents list is not shown.
- [ ] Look at the At a glance strip. You should see a flat strip with dividers between the cells, a label over a bold value, and the status in the figure's own colour with no dot. At 1180 px or less the Project health cell is on its own row.
- [ ] You should see the Milestones switch and its scale joined, and the project title on one line, cut with an ellipsis if it is long.

## Left rule and Add tile (rows 1312, 1260 G11)

- [ ] Open Work items, Milestones, Use cases and Settings. You should see a thin 2 px rule down the left side. The Dashboard has none in the same place.
- [ ] On Work items with rows, you should see the dashed + at the far right of the saved-views row, and not in the page head. Use cases is the same. Milestones has none.

## Classic Milestones (row 1260 G4)

- [ ] Open the Milestones page. You should see no "Every milestone is on the timeline..." sentence under the title.

## Classic Work items page and Edit (rows 1195, 1314, 1309)

- [ ] Open Work items. You should see an underlined filter line (no box) and hairlines between the column headings. Type something the filter cannot read: the underline turns red. At 900 px the view tabs wrap and do not scroll sideways.
- [ ] Open Edit on the Work items list. You should see the gear top right of the title row, then the saved-views tabs, then the filter line, and no pale form bar and no "Choose from lists" panel.
- [ ] Press the dashed + . You should see a 34 px dashed square in every state, and a menu in the order Risk, Action, Issue, Decision, each with a coloured letter tile (R, A, I, D).
- [ ] Open Configure. You should see columns listed Status, Owner, Due, Priority, Workstream, Milestone, ID, then Type, and a Done button that fits the window at 900 px.
- [ ] In the table you should see Ids bold and in the link colour, priority pills with a border, and the Priority pill and its arrow fully inside their cell for Medium, in light and dark.
- [ ] On a project with more rows than the limit, you should see a Show all items link under the rows, and then Show only N.

## Classic Use cases (row 1316)

- [ ] Open Use cases. You should see a plain breadcrumb, plain Group by and Sort by with no arrows, a "..." tab menu, a grey dashed +, a wide search box with a drawn magnifier, and the list as a framed card with a grey header strip.
- [ ] You should see the commitment as a quiet pill under the status pill, and the Next steps count as plain text, not a round badge.

## Cards (row 1269)

- [ ] Pick Cards and reload. On Milestones and Use cases you should see the project name above the title as plain text. On Milestones there is no "is agreed for ..." sentence. The board shows no scroll bars but still scrolls. A menu is 224 px wide with larger text, and the Add button is 28 px high, dashed blue, filling blue on hover.

## At a glance and Dashboard defaults (rows 1303, 1193, 1307)

- [ ] In At a glance Edit, hide a tile with the eye. You should see it leave the edit view, and an "Add a tile" menu list it; choosing it brings it back, and one Undo hides it again.
- [ ] Above 1180 px you should see Project health at half the row beside two tiles, three quarters beside one, and the four-up row with three tiles.
- [ ] Create a new sample project. You should see Risks and issues, Open actions and Decisions as Work items lists, and Decisions including made decisions. An older project keeps its own sections.

## ask clark (rows 1292, 1294, 1295)

- [ ] Open the ask clark panel, go to another page and come back. You should see the chat and the answer still there, and the button showing the number of answers ready.
- [ ] Open a new chat. You should see three plain lines and a link to the Asking card in Settings.
- [ ] Type / in the box. You should see a menu (/check, /summary, /overdue, /risks, /milestones, /usecases, /history, /new) with a hint each; arrow keys and Enter pick, Esc closes the menu first.
- [ ] Open the quick bar and type a question. You should see an "Ask ... in ask clark" row first.
- [ ] Attach a file with the paperclip, by drop and by paste. You should see a chip for each; a sixth file or one over 10 MB is refused with a sentence.
- [ ] When an answer carries a draft, you should see "Draft ready" and an editable Draft sheet beside the panel. Add to the report offers to replace a Text section or add a new one; Esc in the sheet does not close the panel; closing the sheet leaves the report as it was.
- [ ] Open Settings, then ask clark. You should see two tabs, All projects and the open project, with the project tab first and a "Used from All projects" card with a Change button.
- [ ] On the All projects tab you should see Turn on / Turn off for Claude and ChatGPT, a Test the connection button, and the standing instructions box. Type text, click away: Saved. Clear it: Cleared. Text that looks like a password is refused.
- [ ] With standing instructions set, you should see "Standing instructions on." in the status line.
- [ ] Add a folder for all projects. You should see it in a project's tab tagged "All projects" with a Change button.

## Connectors (row 1306)

- [ ] Open Settings, then ask clark, All projects. You should see a Connectors block, "Asking for all projects", with On/Off switches, all Off. On a project tab, only connectors that are On for all projects are listed. If none are found you should see "No connectors were found on this computer."

## Published file and Word (rows 1251, 1307)

- [ ] Publish a sample project whose Plan summary is untouched. You should see that section left out of the file. Type a word in it and publish again: it shows.
- [ ] Publish a project that has a shown Work items list but no Risks, Actions or Decisions section. You should see the Work items tab in the file.
- [ ] Export a Work items list to Word (sample data). You should see an action with its Latest update line under the item text; risks and decisions have none.
