# Hand-check sheet for clark 1.2.0

Written for the person who looks at the screens after the release. One line for each thing a person can see that changed; only what a test cannot decide. Hand checks never hold up a release.

**Sample data only.** The fictional demo projects. Run `bash clark.command --demo` in the unzipped clark folder. Laptop only: Chrome at 1400 px wide, then again at 900 px. Light and dark where a line says so. Do not press Export, Save or Publish on real data.

Each row: PR, what to check by hand, and what you should see. Tick each line; write what you saw where it fails.

Screens changed since 1.1.1: Project at a glance, Work items list, Callout, peek Latest update and Rating chip, use case Owner, Gantt toolbar, default report, published bar. Every line is taken from the merged PR text; words in quotes are the PR's words.

(r7, 11-18: origin/main head d0686ec33; built from the first-parent merges since v1.1.1. Lines below that a test cannot decide; hand checks never hold up a release.)

## Work items list (row 1268: PRs 1794, 1796, 1821, 1822, 1823)

- [ ] Edit, Dashboard: add a "Work items list" from the library. You should see a heading, a filter, a live list and an optional caption.
- [ ] Look at the saved views above the list. You should see them as tabs, a dot and "Save view" / "Discard changes" when the list has moved off the tab, "+ New view" (an empty name is refused), and the Add menu at the right end of the same row, right of the last tab and of "+ New view". Check at 1400 and 900.
- [ ] Open Configure on the list. You should see Sort by, Most rows, Columns and a Footnote, and the footnote under the list.
- [ ] Make the list longer than Most rows. You should see the rows scroll, the line "Showing N of M" and "Review all N items"; pressing it opens the Work items page on the right type (actions, risks, issues, decisions).
- [ ] Right-click a column heading. You should see a menu called "Columns" of checkable columns; a ticked one is shown.
- [ ] Click a row. You should see a read-only peek. Edit a cell in place and drag a column width; each change keeps.
- [ ] A Decisions list: the mode line reads "Open, and decisions made in the last 14 days". A row without a rating says "Not rated".
- [ ] Hide the built-in Actions section and keep a list that names an action. You should see the list still show its rows, in Edit and in the published file.
- [ ] Export the Word report (sample data). You should see a "Work items" heading with the list as one table; a row due yesterday says "Yesterday", a later one "N days late"; a decision that is not Pending gets no late words. A client workbook (sample data) carries the same rows.

## Callout (row 1272: PRs 1806, 1809, 1813, 1832)

- [ ] Add a Callout from the library (group Project information). You should see a tinted box with an icon and the category word, and no stripe; Plain has no box.
- [ ] In Edit use the toolbar: Category, Colour (Plain, Violet, Amber, Red, Green, Grey), Icon ("Choose an icon"; 20 icons and No icon), Show Tile, Show Heading (an eye icon, open when on, struck through when off). The title counter reads "Title N of 120".
- [ ] Open an older callout (a file from 1.1.1). You should see it unchanged, with its old tone word.
- [ ] Publish to a test folder and open the file. You should see the same look; with a screen reader, "Colour: Violet. Icon: Light bulb." is read (the Icon part is left out for No icon).

## Peeks (row 1257: PRs 1803, 1804)

- [ ] Open an action, risk, issue and milestone peek in Edit at 1400 and 900. You should see the Latest update as one bordered card, the footer strip "⌘ Enter to save" always shown, and a stamp "last updated dd-mm-yyyy hh:mm" under it, no clock icon. The empty box says "What changed? Add the latest update…".
- [ ] Open a risk or an issue, click the Rating chip. You should see a matrix 268 wide with Low, Medium, High above the cells; the level pill is bold and the chip icon takes the colour tone. The tip reads "Priority from impact and likelihood" for both.

## Use cases (row 875: PR 1805)

- [ ] Open a use case page and click the Owner line in Details. You should see a box; Enter or leaving it saves one change with one Undo; Esc puts the old owner back and sends nothing.
- [ ] Type more than 200 characters. You should see the change refused and the old owner kept.
- [ ] Publish and open the file. You should see the owner as plain text, or no Owner line when there is none.

## Gantt (row 1197: PR 1756)

- [ ] Open the Gantt page at 1400 and 900. You should see no "Table" word button; table and chart icon buttons first in the chart's bar beside Week, Month and Quarter (in the table view, in the page bar), Zoom out, the percentage and Zoom in beside the Show filter, then Today and full screen. With no View or Edit button there is no empty bar above the chart bar.

## Default report and published bar (rows 1266, 1228: PRs 1824, 1755)

- [ ] Start a new project and look at the sections. You should see ten sections, with Current state first and no Summary. An existing project keeps its own Summary.
- [ ] In Help, the how-to step says "Click the text under Current state, This week or Next week".
- [ ] Publish a test file. You should see the project name in the bar in the same heading face on the Dashboard, Work items, Use cases and Milestones tabs.

## Filter line and saved views (row 1265: PR 1818)

- [ ] Open a Work items page, change the filter on a tab (core tab too). You should see the tab's small-arrow menu say "Update view" (not "Save changes"); choosing it keeps the change. Check at 1400 and 900.
- [ ] With unsaved filter changes, leave the filter line. You should see "Save your changes to this view?" with "Update view", "Save as a new view" and "Discard"; Esc closes it; clicking inside the filter box does not open it. "Save as a new view" makes and chooses a new view and leaves the original's saved line unchanged.
- [ ] Open Help, Filter guide. You should see it name Update view, Save as a new view and Discard, and no "Save changes".

## Published page: Image gallery (row 1233: PR 1761)

- [ ] Publish a report with an Image gallery section, open the file at 1400 and 900. You should see the pictures in a grid; click one: it opens larger with its caption; Esc, a click outside and the close button each close it.

## Update by eye

- [ ] Update from inside clark from 1.1.1 to 1.2.0: the safety copy is made first and the data opens as before. The store moves up three steps (27, 28, 29) and nothing visible changes; a file brought up keeps the look it had (Clark Cards).

## Project at a glance (row 1264: PRs 1849, 1850, 1851, 1852, 1854, 1855, 1868; all merged)

Words and looks are taken from the PR texts. Check at 1400 and 900 only, light and dark. No PR text says it was looked at by eye; each says macOS and some say screen reader were not checked.

- [ ] PR 1850. In View of a section of the glance template: the three counting tiles (Overdue actions, High risks and issues, Decisions needed), then the section's own tiles; each tile has a thin grey border, a coloured edge fading from the top left, the dot, the tag word on the right and the note below; the dot shape tells the tone (circle green, triangle amber, diamond red, rounded square blue, ring neutral). Notes and labels wrap and are not cut. A counting tile opens Work items with its filter; own tiles do nothing. With every tile switched off it reads "No tiles on this section." A counting tile with no rows is left out. At 1400 and at 900 four tiles on a line.
- [ ] PR 1850, Edit: each of Project health, Overdue actions, High risks and issues, Decisions needed has a grip (drag, or Alt with the arrow keys) and an eye (hides it from the published report); a right-click on a counting tile gives an Outline colour menu (Project health has none); one change is one Undo. PR text: a published file draws only own tiles until the store step lands (not in 1850). Do not claim the published file shows the counting tiles.
- [ ] PR 1854: the tile editor in Edit: Add a tile, the pencil, Done and Cancel, Remove tile, five colours (Green circle, Amber triangle, Red diamond, Blue square, Neutral ring) with the words On track, At risk, Off track, Info under them; Done on a new tile toasts "Added: <label>", on an existing tile "Tile saved"; Cancel or Esc stores nothing; inputs stop at the limits; the five colours show five border colours at 1400 and 900, light and dark.
- [ ] PR 1855: the switch "Project health on its own row"; the eye on Project health hides it and the button "Show project health here" brings it back in Edit; two buttons "Tiles on a line" 3 and 4 (4 is the default); a half width section draws 2 on a line and Edit says "Half width always shows 2 on a line."; the library card "Project at a glance" in Figures (full or half) with its sketch of three low tiles edged red, amber, green, and its row in Help. At 900, View draws 4 on a line at full width and 2 at half width; Edit draws one tile per line (kept on purpose).
- [ ] PRs 1852 and 1868 (the print slice), sample data only, never real data: the Word report prints the glance section as a table, tiles four to a line (3 or 4 by Tiles on a line, 2 when half width, short last line padded), the health tile in its place or as a shaded label with a bar of the project's colour and the reason; the client workbook has one sheet per glance section with heads Tile, Figure, Tag, Note, one row for each tile. Open the Word file in Word and look at the print preview: both PRs say this was not done.

Not checked by anyone (taken from the PR texts): macOS; screen reader; Word and Excel opened in the real applications and print preview; the focus after Pop out in the tile editor; the PR texts of 1850, 1855 and 1856 do not say a line-by-line match with the ticket or the v2 mock-up was done (1855 and 1856 say not checked). A width of 760 px and below (one tile per line) is not a width of this sheet and is not checked.
