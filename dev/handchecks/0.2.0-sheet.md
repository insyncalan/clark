# Hand-check sheet for clark 0.2.0

Written for the person who looks at the screens after the release. It is the short list: only what a test cannot decide. Everything else is covered by `tests/test_v020.py`, which names a covering test for each check and fails if one goes missing. Hand checks never hold up a release; this sheet is for afterwards.

**Sample data only.** The fictional demo projects. Never use a real client's data for these checks.

## Setup

1. In the top folder of the release, run `python3 -m clark --demo --open`. clark opens in Chrome on the demo projects.
2. Chrome at 1400 px wide, and again at 900 px wide for the checks marked *(both widths)*. Light and dark: the profile circle, top right, has Dark mode.
3. For the Excel checks, have Excel (not a viewer) open. For the client folder check, a real OneDrive-synced folder you can see syncing.

Tick each line; write what you saw where it fails.

## The screens (judgement)

1. **Change in place.** In Edit, change a status, a priority, an owner and a due date by click and then by keyboard. Each is one step; Undo undoes it. Nothing here looks cramped or jumpy. *(both widths)* [ ]
2. **Dragging a section** feels right: it shows where it will land, and drops there. [ ]
3. **Milestones.** The timeline shows each milestone at its date; zoom in and out; the colours are easy to tell apart; a slipped milestone shows its marker and the days. Switch to Calendar and back. The legend reads clearly under both. *(both widths)* [ ]
4. **At a glance tiles and the use cases strip.** The health tile is wider than the others and the status words in the use cases strip line up in one column. *(both widths)* [ ]
5. **Dark mode is pleasant to read** on every page: nothing glaring, nothing hard to read. *(both widths)* [ ]
6. **The published file** reads well and looks right to a client: open one produced from the demo projects and read it as the client would. [ ]
7. **The import plan's lines** (Excel import, before you apply) read well, including the line for a new row's ID. [ ]

## Live only (cannot be tested by a machine)

8. **Back and Forward by trackpad.** Open Work items, then Milestones, then Settings. Two-finger swipe right-to-left goes Back one page at a time. Swipe the other way for Forward. The mouse's back and forward buttons and the keyboard do the same. [ ]
9. **A To client publish** arrives in the real client folder, and syncs to the client's side. The copy is the same file. [ ]
10. **In Excel,** dropdown arrows show on the fixed-value columns, and a wrong value gets the plain error box. [ ]
11. **In Excel,** a value you change by hand takes its colour; an overdue date is red. [ ]
12. **In Excel,** the ID column is shaded and its note reads well. [ ]
13. **The brand picture on the Cover sheet** (only if a logo is set up in your local brand folder; skip otherwise) looks right and sits at the right of the band. [ ]
14. **Settings › Safety.** The backups are listed newest first; Preview one, then Restore it (do this on the demo data only). The earlier data is back, and the words on each step read plainly. [ ]
15. **Restore from Terminal.** Make a change, then follow the written restore steps once, exactly as they stand in the README (`python3 -m clark restore`), with clark closed. The earlier data is back. [ ]

## Not in this release

The peek panel and Sneak peek (0.2.1), Word, ask clark, rich text formatting (the editor is switched on later), Windows and Linux downloads. Do not check them.
