# clark 1.0.1 (Beta), Mac

This is the 1.0 build. It is still marked Beta because updating from inside clark is not switched on yet.

This version includes a change to how clark stores your data. Read this first.

## Read this first: a change to how clark stores your data

- One change to the data file format (from layout 15 to 16). clark makes a safety copy of your data before it changes anything.
  - Step 16: each use case can now carry a flag, Candidate, Committed or Planned 2027. Every use case you already have starts with no flag, so nothing you see changes.
- An older clark (1.0.0) refuses the new data file: "This data needs a newer clark. Nothing was changed. Install the latest clark, then try again." Once this version has opened a project file, open it only with this version or a newer one.
- Going back to 1.0.0 means putting back the safety copy clark took before the change. It is listed as "before an update" in Settings, Safety, where Preview and Restore are beside it. Or, with clark closed, type `bash clark.command restore` in the clark folder to list your copies and put one back. First restore the safety copy, then open it with 1.0.0.
- Updating from inside clark is not switched on yet: install a new version by downloading it and replacing the old one.

Theme: ChatGPT and Claude on the Settings AI card, Excel in and out, a client menu on the published report, and a steadier Dashboard and Settings.

## What is new

- Settings has an AI card: connect Claude or ChatGPT and ask clark uses it. The card has a tile for each, saying Connected or Not connected, with a Connect or Disconnect button, and a Model for ask clark list; if you choose a smaller model, the card asks first (Use it anyway or Keep the model I have). No password is asked for: the Claude or ChatGPT command already signed in on this computer is the one used, and what you ask goes to the one you use.
- A use case can carry a Commitment flag: Candidate, Committed or Planned 2027, or no flag. A new use case starts with no flag, and the use cases you already have show nothing until you set one. In Edit a small Commitment menu beside the status has the three words and No flag. The flag shows as a chip beside the status on the Use cases tab and in the Dashboard rows, and the client sees it in the published report; the eye still hides the whole use case. The Word copy's use case table has a Commitment column. History shows "changed the Commitment from X to Y", and Undo puts it back. The Excel export has a Commitment column after Status with a drop-down of the three words; on import a wrong word is reported by row and an empty cell leaves the flag as it is. The Use cases section of Help has a line about it.
- Help has a new entry, Connect Claude or ChatGPT, in the Settings and safety group, with the steps for the AI card.
- Help describes ask clark and Sneak peek as they really work. ask clark changes work items and milestones, never use cases. Sneak peek changes work items only, in Edit. The / key opens ask clark and / / opens Sneak peek. The Start part has one line for the ask clark button in the top bar, and the key list no longer shows keys that do nothing.
- Help now describes the search button and the Go to or do box, the typed filter on Work items, the Settings chips, what happens to the ask button when asking is off, the commands that start, check and restore clark, and the real Excel column names. As each feature arrives, Help also covers the Report menu in a published file, the week-ending calendar, choosing which sheets to import, the Excel cover and tabs, and the Commitment flag. ## What is fixed

- At 901 px wide the Work items and Use cases tabs in the top bar no longer wrap onto two lines; the project name shortens first.
- Starting clark with Docker for the first time from a fresh download, with CLARK_DATA_DIR set, now works. Before, Docker could not create the data folder and clark did not start.
- A message that names a folder outside your home folder, such as the OneDrive message, now shows the real path. When clark runs in Docker, the line it prints says how to stop it: docker compose -f docker/compose.yaml down.
- The line under the Help search count now says only what each result shows: "Each result names the guide and the step it is about."
- In Help search, that line shows only when the results include a guide.
- On a fresh install the ask clark panel no longer flashes "Asking is off" before the server has answered.
