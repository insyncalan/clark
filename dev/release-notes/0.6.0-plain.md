# clark 0.6.0 (Beta), Mac

Beta means the whole of clark is Beta until version 1.0.

This version includes a change to how clark stores your data. Read this first.

## Read this first: a change to how clark stores your data

- Two changes to the data file format, in two steps (from layout 9 to 10 to 11). Step 10: each publication now has a number, one count for each project. Step 11: a use case can be marked Done. clark makes a safety copy of your data before it changes anything.
- An older clark refuses the new data file: "This data needs a newer clark. Nothing was changed. Install the latest clark, then try again." Once this version has opened a project file, open it only with this version or a newer one. To go back, restore the safety copy.
- The Install button in Settings will not install this update, because it changes how your data is kept. Download the update and install it by hand.

## What is new

- Each publish gets the project's next number (Publication 1, 2, 3). It is shown at the foot of the published file and in the publish message, a Local-only publish takes one too, and a Preview does not. A number is never reused. History gets one line for each publish, shown under All.
- A use case can be marked Done, from the status menu in Edit. It is saved as one step with one Undo, shows the word Done in grey (not colour alone) in View, on the dashboard rows, in the strip's count and on the published page.
- Publish shows a turning circle while it works, then a tick with the publication number.
- Text sizes come from one shared scale, in the editor and in published pages.
- The week ends on a Friday everywhere. Week ending must be a Friday: clark refuses another day and names the Friday to pick, and This week in Work items runs to the coming Friday.
- Ten small motions (publish circle and tick, loading placeholder, changed-row mark, peek fade and slide, drop line, health settle, timeline and calendar swap, handle hint, count fade, Add a section preview). With Reduce motion on, nothing moves and a still mark shows instead.
- Milestones page: a heading with the project name and one sentence on the agreed and expected dates; a + button (in Edit) to add a milestone; Add a recovery action and Escalate to steering on a movement; an internal note on a milestone that is never published.
- Milestones: the eye on an internal-only milestone is greyed and says so. Archived rows show the agreed date and how many work items are linked.
- Work items: owner, due, priority and status can be changed in View too, in the row. A published file has no pickers.
- Work items: Up and Down arrow keys move through the rows of the table and the cards of the board; Enter opens the peek. Left and Right also work on the board.
- Use cases: each next step shows its owner's initials.
- At 1180 px wide and below, Project health has a row of its own on the dashboard.
- Work items: one filter line above the list in the app replaces the Filter by row; type words or use the arrow keys, and press / to reach it. A published file keeps its older filter bar.
- Published reports: a card in Settings and a line in the profile menu list the open project's publications, newest first, each with its number, date, where it went and who published it, and open the kept copy of the page.
- Publish has a PDF option (needs Google Chrome on this computer). The PDF is saved beside the report file, and copied to the client folder when To client is ticked.
- Settings: the page has a title, a help line and a chip for each card to jump to it.
- Milestones: the details can be hidden or shown (remembered for each place), and a Plan or Movement switch sits at the top of the page.
- Work items: an intro line at the top, an Export button beside Add (Edit only), and compact board cards with a letter badge; in Edit the card dots are always visible.
- Dashboard: risks, issues, open actions and decisions are drawn on it, and in Edit a hint under the tiles says to drag a tile to reorder.

## What is fixed

- Adding a section below the last one no longer carries an old "beside" mark; it is cleared in the same step.
- Preview refuses a section style clark does not have, in the same words Publish uses.
- Contents list: the button keeps its name and Esc closes the list after a click.
- The served page no longer offers a Client report tab. A published file still has the Weekly snapshot tab.
- Tracker messages before a save (percent, length, total) say what to do, in plain words.
- About you: a refusal shows under the box it is about, and the other box keeps what you typed.
- "I sent it" records your own local day, not a UTC day that the store may refuse.
- "I sent it" refusals are in plain words and end "Nothing was saved."
- Undo several names the steps it would refuse, with the reason, and the Activity tab withholds the tick on them.
- Undo with the key when there is nothing left says: "Nothing to undo since this page was opened. Older changes are in Activity."
- "I sent it" now refuses an item with a label that is left out by default, and a second press from another tab or window is counted once.

## Passwords and keys

- Words such as "placeholder", "redacted" and "example" in quotes after a password word are treated as placeholders. "Password" and "secret" in quotes are no longer placeholders, so they are caught.
- Short sk- keys, short API or access key values and "API key:" with a space are now caught. Quoted text and lines joined together are no longer refused by mistake, and base64 keys are still caught.
- A password or key that falls across the 4,000-character cut of a report row is left out whole, not sent in part.

## Ask clark

- The password and key check covers the assistant's earlier replies as well as your messages, runs before your question is read, and the refusal says it found a password or a key.
- Ask clark refuses every kind of secret the shared check knows, not a shorter list.
- If the answer service fails, its failure message is checked for private text like a reply, and a plain refusal is shown instead.

## Help

- Help says ask clark refuses a value that looks like a password or a key, not a plain word, and when the profile menu's Publish, Preview and Export lines appear.
- Help has entries it was missing, for Movement, Diagnostics, Report sections, Needs from you, Freshness and project health.
- Help: nine reference entries that were held back are now shown, and the arrow keys have rows in Help.
- Help says the week ends on a Friday, and that each publish gets a number.
- Help has steps for finding a past publication and for saving the report as a PDF, and its held entry on use cases names only buttons the page has.

## Behind the scenes

- Tests only: speed tests use load-proof CPU ceilings; the tracker and inline-edit tests wait on the page's own state; the undo-limit test quotes the real words. The test build checks a guarded file by its full path.

## Corrections to the earlier notes

- The week-ending date on the report bar can be changed in Edit only. View shows it as text.
