# clark 1.1.0 (Beta), Mac

This is the 1.1 build. It is still marked Beta: it works and is tested, but expect rough edges and changes between versions.

## What is new

### Dashboard

- Add a section now offers At a glance, Use case summary and Milestones as cards, each with a short description, its parts and a Help row. Each makes the same section as before, at full width. Placing one beside another section is refused with "This template needs the full width. Place it on its own row."
- Dragging a section now shows a ghost of its title that follows the pointer, a faint dashed outline where it came from, and a dashed half or a line where it will land. The section glides into place, and the page scrolls when you drag near the top or bottom edge. Help describes the new drag.
- A Full width image section: one image runs the full width of the page, framed by clark (Whole image, Shape 16:9, Strip 3:1, or Free height from 1:4 to 4:1), with an optional caption and description. Only the framed copy is published, and the Word report uses it too. The older Image with caption is unchanged.
- The Work items section can show Priority and Milestone columns. A new section starts without Status, Workstream and Milestone; sections you saved keep their own columns. Status now shows a half circle in the colour of its pill. A Show all items link under the table opens the rest, and Show only N goes back. A published file has no link.
- A file listed in a documents-and-links or one-document section now has Open and Download buttons in the editor.

### Work items

- A decision has a Priority (Urgent, High, Medium or Low, Medium by default), set in its peek. The list, the board and a bulk change still refuse it, and say: "A decision's priority is set in its details, one at a time."
- Right-click a table heading, press the Menu key or Shift+F10 on a focused heading, or use the Columns button, to choose which columns the Work items table and the Milestones list show. Title and status (Work items) and name and state (Milestones) cannot be turned off, and say why. "Show the standard columns" puts them back. The choice is kept for each table and project in this browser only. A published file and the Excel export are not changed.
- The eye now says what it does: "Take <id> <title> off the page" or "Put <id> <title> on the page", with the shorter "Take off the page" and "Put on the page" as the tip.
- Dragging a column heading to change its width now works on the Settings pages Projects, Published reports and People too. Each is remembered per table on this computer.

### Peeks

- Every peek has a new frame: a toolbar, an ID line, an editable title, a row of chips and the details below. The Action peek is built on it.
- A risk, an issue and a milestone have a Latest update in their peek, with an unsaved bar, a history link and "Shown to the client". A milestone's Latest update is published and carried in Excel; a milestone with no client wording leaves it out. Toasts say "Latest update of <id> saved." and "Latest update of <id> cleared."
- A quiet Draft with AI button, with a sparkle icon, sits beside Latest update on the Action, Risk, Issue and Milestone peeks, in Edit only. Right-click on selected words in Latest update (or Shift+F10 or the Menu key) opens the same AI menu over just those words. Nothing changes until you press Accept.
- The Decision peek has new fields: Made by, Made on (Needed by while Pending), Priority, Reasoning, Options considered, Revisit, Replaces, Visible to client and Latest update.
- A risk and an issue both have a Rating chip that opens one 3 x 3 matrix of impact and likelihood. One click sets both, as one change with one Undo. The arrow keys move over the cells, Enter or Space picks and Esc leaves it as it was. Neither peek lists Red, Amber and Green as a status any more; a closed one says "<colour> kept".

### Use cases

- The Use cases page shows the project name above the heading, and the grey line under the heading is gone.
- The list has column names over the rows: Use case, Where it stands, Status and Next steps. Archive and Delete move from a More button to the right-click menu.
- The open tab has an options menu (Rename view, Move view, Duplicate view, Delete view with Undo), and a + New view button sits beside the tabs.
- The Use case summary has a Configure button in Edit. Its panel sets how many use cases are shown (a number or All), whether viewers can scroll the list, and where the status tracker (the count pills and the bar) sits: Top, Bottom or Off. Each change saves at once, with one Undo. A published page holds none of the Configure panel.
- The Use case summary in View is a table with a heading row and fixed columns. The whole row opens the use case, and an empty Commitment shows a dash. Edit keeps Set commitment.
- Adding a use case from your project record now uses a table with a filter panel: a search box, ticks, Select all shown, Cancel and Add. When nothing matches, it says "Nothing matches your search...". Add shows no number until something is ticked.

### Ask clark

- The question box grows with what you type, from one line up to five, then scrolls inside. It keeps room above the first line and below the last, and Ask stays at the bottom right.
- While ask clark works, a solid square Stop icon takes the place of the Ask arrow in one round control. The separate Stop button is gone, so the box keeps its width.
- Press Enter while ask clark works to queue what you typed. Queued messages show as small lines above the box, each with a bin named "Remove this message". They send themselves in order as each answer lands, up to 5 can wait, and each gets its own answer. After Stop, or after a question with no answer, they wait, with Send them and Clear.
- Answers are drawn formatted (bold, italic, code, headings, bullet and numbered lists, fenced code) instead of showing the marks as symbols. Links, images, tables and HTML stay as plain text.
- When a whole section is left out of the report, ask now says which kinds are left out, so a missing kind is not read as "none exist". Help says the same.
- Connect finds Claude Code when it was installed only by the VS Code extension. The file must still pass every existing safety check.

### Settings

- Settings has a menu down the left, grouped as Everyday, Publishing, Look and feel, Data and safety and Advanced, and shows one page at a time. The page is in the address, so Back and Forward move between pages, and each page keeps its own scroll place. Search still looks at every page at once.

### Published report

- A published report's header has the date back in the bar as a button ("As at DD-MM-YYYY", tip "Click to change date"). A click opens a calendar. A day with a past report opens that report. Any other day says "No report for DD-MM-YYYY.". "As at" also sits at the foot of the profile menu.

## What is changed

### Dashboard

- The Current state section publishes its own text, and publishes nothing when that text is only the grey hint shown in the editor.
- The editor header matches the new design: one smaller logo, a larger project name, the tabs and underline moved into place, and the second logo at the right removed.
- Scrolling over the ask panel, its answers and saved chats, the Peek, the Add a section box or a dialog only scrolls that panel, never the page behind it.

### Ask clark

- The notes about what ask left out are one small grey block of notes under Sources, instead of a paragraph each.

### Published report

- The cover line no longer says "for <client>".

## What is fixed

### Ask clark

- Pages of a PDF, and parts of it, that ask clark did not read now count in the "left out" note, so the note no longer says nothing.


### Work items

- After Esc, the focus goes back to the element that opened the columns menu, and a milestone row's name now lists the extra columns shown, so a screen reader reads them.

### Settings

- The Feedback contact box and the Brand select show the same focus ring as the other fields.
