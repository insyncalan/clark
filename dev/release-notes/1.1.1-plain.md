# clark 1.1.1 (Beta), Mac

This is the 1.1 build. It is still marked Beta: it works and is tested, but expect rough edges and changes between versions.

## What is new

### Dashboard

- The Milestones section has a Configure button in Edit, like the Use case summary. Its panel sets how many milestones are shown (a number or All), whether viewers can scroll the list, and where the status tracker (the count of milestones in each state, which also works as the key) sits: Top, Bottom or Off. A published page holds the same settings.
- The Milestones section is now a table with a heading row: Milestone, State, Agreed, Expected or achieved and Progress. Under the date, a small line says "Forecast", "+N days" or why a milestone is not going ahead. Its calendar scale is drawn as plain tabs at the right.
- In Edit, a note under the Milestones list says how many milestones show at a time and whether viewers can scroll, so what you see is what viewers get.
- You can move a section from the keyboard sideways as well: with the move button focused, Alt+Right puts the section beside the next one and Alt+Left makes it full width.
- While you drag a section, a line under the page says what letting go would do, for example Release to put "Title" beside "Other title", half width each. After the drop, a screen reader hears what was done.
- On a touch screen, a finger holds on the move button for a moment before the drag starts, so a quick swipe still scrolls the page.
- The box that adds a milestone back from your project record now uses the same table with filters as the use case box, with a search for name, ID or state and a tick in the heading to select every row shown.
- In the Use case summary, the number of open next steps is a round badge, and the use case list on the Use cases page uses it too.

### Peeks

- The Milestone peek in Edit has a row of chips under the title: State, Owner, Progress and Forecast date. State opens the five you can pick, Progress is ten blocks you press, and the Forecast date chip opens a date picker. A late forecast shows "overdue N days".
- The Milestone peek has a Latest update box, like an action, a risk and an issue. Its details now list Description, Agreed date, Workstream, Use case and Client wording, then a Client visible line.
- A risk or issue peek draws its Details like an action: Workstream, Milestone, Raised and Use case, then the Client visible line. Its Status chip says Open, Closed or Cancelled, and the Rating chip carries the colour word with its level as a small badge.
- An overdue action's Status chip says Open, and the lateness shows on the Due chip. The chips in a peek now sit side by side as one flat row.
- In View and in a published page, a peek shows a read-only Client visible or Client not visible line.
- The Activity list in a peek shows stored dates as DD-MM-YYYY.

## What is changed

### Dashboard

- The Use case summary no longer has its own Add use case button in its header in Edit. A use case is added from the Use cases page. The header keeps Configure.
- The Configure note now says Edit scrolls whenever a number is set, so you can reach every use case, and viewers scroll only when it is On.

### Peeks

- An overdue date on a peek chip keeps the chip's normal colour. Only the date is red, and "overdue N days" is a small red badge.
- Help now describes the new peeks, the Rating chip, the Configure panel for Milestones, and the Alt+Right and Alt+Left keys.

## Windows

The Windows download is a zip, not a native build. You unzip it and run clark in Docker.
