# clark 1.0.3 (Beta), Mac

This is the 1.0 build. It is still marked Beta because updating from inside clark is not switched on yet.

This version includes a change to how clark stores your data. Read this first.

## Read this first: a change to how clark stores your data

- One change to the data file format (from layout 16 to 17). clark makes a safety copy of your data before it changes anything.
  - Step 17: each action, risk and issue can now carry a Needed from the client flag. Every item you already have starts with it off, so nothing you see changes.
- An older clark (1.0.2) will not open the new data file: "This data needs a newer clark. Nothing was changed. Install the latest clark, then try again." Once this version has opened a project file, open it only with this version or a newer one.
- Going back to 1.0.2 means putting back the safety copy clark took before the change. It is listed as "before an update" in Settings, Backups, where Preview and Restore are beside it. Or, with clark closed, type `bash clark.command restore` in the clark folder to list your copies and put one back. First restore the safety copy, then open it with 1.0.2.
- Updating from inside clark is not switched on yet: install a new version by downloading it and replacing the old one.


## What is new

- The project menu in the top bar now ends with New project... It opens the same form as Settings, Projects, and the new project opens on Work items. The menu opens on the project you are in.
- In Edit, Ctrl+J (Cmd+J on a Mac) opens ask clark from anywhere, including while you are typing in a field. The ask clark button's tooltip now reads "Open ask clark (/ or Ctrl or Cmd + J)".
- The two switches in Settings, Asking and Single-key shortcuts, now say what they were turned to ("ask clark is on", "Single-key shortcuts are off" and so on) in a message with Undo, which sets the switch back. The message goes when you leave the card.
- The eye on a work item can now be clicked in View as well as in Edit, on the Work items list and on the Use cases list. On a Work items board the card's eye is now a button too, with the same message and Undo.
- On Work items, when nothing matches the words you typed, the list says, for example, No open items match "crane". (or No items match, when All or Closed is chosen), offers Clear search, and adds a hint: "Plain words search titles. Press / to come back here."
- On a use case, a work item in the list and a linked milestone's name each open their peek beside the page; the page stays where it is. A linked milestone also shows its state, with the same word and mark as the Milestones page.
- The Client Excel workbook's sheets are now protected without a password, in the same way as the export's sheets. The ID column, the worked-out columns (Original, Shown state) and the other columns the export locks are locked; to change a locked cell, use Review, Unprotect Sheet.
- Sneak peek (press / twice in Edit) now also changes a milestone and a use case in words. For a milestone: its forecast date, achieved date and status; marking it Achieved, or reopening an Achieved one, asks first. For a use case: its status, commitment and headline; Done asks first. A milestone's owner and agreed date cannot be changed there. On a use case it works on the use case's own page.
- Add a section now offers six more templates: Image gallery (pictures in a grid, each with a caption), Table, Image with caption (one picture with its caption), Quote, Contacts and Checklist.
- The page has a Skip to content link for keyboard users. It is the first Tab stop and shows only while it has the focus; Enter puts the focus in the main part of the page.
- The command palette lists Pages, then Actions (Add action, Add risk, Add issue, Add decision, Add milestone), then Projects, then Commands.
- The Excel workbook and the client workbook now print landscape on A4, one page wide however many pages tall, so the Cover no longer splits across pages. In the Excel workbook the values in the Cover tiles are inset a little from the coloured edge.
- On the Milestones page, a milestone's peek now changes its name, owner, workstream, progress (0 to 100) and description in place, without Edit. Each change is one step with one Undo, and a milestone cannot be left without a name. An owner change links the person it names, as for a work item.
- Import from Word is in the profile menu whenever a project is open, without Edit, and Settings no longer shows the View | Edit pill. Help says so.
- Milestones no longer need Edit: Add milestone, the eye, and Movement with its choices work as soon as you open the page. The Dashboard in View and a published file still change nothing.
- The peek of an action, a risk or an issue has a Needed from the client switch, with the line "Lists it under Needs from you". One click is one change with one Undo, and History calls it Needed from the client. A decision has no such switch.
- In a published report, the actions, risks and issues that are open (Open or Delayed), shown to the client and switched on as Needed from the client are listed under Needs from you, after the rows typed there; a decision is never listed. Each is listed under the client wording if it has one, else its description.
- Under each ask clark answer that used files there is a closed Sources list; open it with Enter or Space to see the files. A part suffix is dropped and each file is listed once. With no files there is no Sources list.
- The ? peek, and the Help entry in the profile menu (the same peek), list the how-to articles for the page that is open under the heading How do I… ; choosing one opens it in the full Help. Open full Help stays at the foot of the peek.
- The command palette now also searches your data when you type: work items and milestones by words, ID or owner, and use cases by name, headline or ID. The matches come straight after Pages, up to eight of each kind.
- The Help page, Start here, opens with a hero card and The loop, five steps with one marked Your call, above the jobs. The loop's introduction reads: "Every week follows the same five steps."
- Dialogs, and the dimmed page behind them, ease in.
- Menus and pop-ups drop in a few pixels as they open.
- A field you change in the peek flashes once and settles. With reduced motion it is a steady tint.
- On Work items, opening a group makes its rows glide in (the peek itself does not glide).
- Buttons and some cards (the Dashboard tiles, the Help job cards) change colour as you point at them, and lift a pixel; they are flat again while pressed.
- A message and its Undo button rise in from the foot of the window.
- The check mark that ends a publish draws itself.
- The View | Edit highlight glides from one to the other, and the Edit controls fade in.
- The ask clark panel rises from the bottom of the window when it opens and sinks when it closes.
- Placeholders that stand for a screen still loading shimmer.
- On the Work items board, a card you drag lifts, the column it would land in eases its highlight in, and a column dragged by its heading lifts too.
- The count on a board column ticks when it changes, the Undo button on a message pulses once, and an eye blinks once when you press it.
- A tab change fades in and rises a little on the pages clark serves; a redraw in place and a published file do not.
- All of this motion is left out when your computer asks for reduced motion, or when clark's own reduced-motion setting is on.
- The Use cases page no longer needs Edit for these: an archived list under the list (Show archived, with Restore for each), Add a use case and Export to Excel in the page header, and on a use case's page + Add a next step and + Link an existing work item. A published file has none of them.
- In the Dashboard editor every kind of section can be deleted from its menu (Delete section); a built-in section you have deleted can be added again from Add a section, one of each. A deleted built-in section is not in the published report.

## What is changed

- On Work items, a click on a row or a card now opens its peek and selects only that item; a double-click is no longer needed. Cmd or Ctrl+click and Shift+click still only select. Help says so.
- Help now says that the links to the Settings cards are a list down the left of the cards, and a row of chips under the title in a window 900 px wide or narrower.
- Messages (toasts) are now a rounded pill, centred at the foot of the window, with the text centred.
- Settings, Personal: the Keys group is drawn without a box round it, like the other groups.
- On a use case, the line above the title (Use cases, then the use case) is now in tracked capitals, and its link is underlined only when you point at it.
- The change card in the ask clark panel has a quieter look: a thin blue edge at the left, a light background, and a small flat button labelled Apply at the left.
- The Milestones calendar's Week, Month and Quarter choices are one rounded group with the chosen one filled, and the Today button is as tall as the group.
- On a use case in Edit, Change status has a gap between its words and its arrow, and the buttons beside it are the same height. The Commitment menu now starts with the heading "Commitment".
- In the Milestones calendar's Quarter view, every milestone is a small marker with no text; its name, date and state are in its tooltip, and a click opens its peek.
- With Asking turned off, the ask clark panel keeps its greeting, its suggestion buttons (greyed out) and its box (greyed out), as well as the line that says asking is off.
- The "Answer" and "You" labels over the messages in the ask clark panel are no longer drawn. A screen reader still reads them.
- The clark logo in the top bar is now a button that goes Home (the Dashboard). A published file's logo is still not a button.
- The client Excel workbook's dates are left-aligned, so a date no longer runs into the Status that follows it.
- In the Word copy, the table columns are wide enough that an ID, a date or a status word is not broken across two lines. This changes the use cases, milestones, actions, risks and decisions tables.
- On Work items, the right-click menu on a row opens once at the pointer. The short lists for status, due date and owner open beside their entry; the menu itself no longer moves or changes size, and the Back entry is gone. In the short list, Left or Esc goes back to the entry.
- Milestones: while nothing is archived, the Show archived button and the empty Archived box are not drawn. The first archived milestone brings them back.
- The Word copy lists only open actions, risks and issues; closed ones stay in Excel.
- The published footer gives the date once and no longer says View only.
- The project form is laid out with each label at the left of its field, every field has a visible border, and the box is centred in the space below the top bar.
- In the project menu each project is its name with its count of open items on a line of its own under it; a long name is cut with an ellipsis.
- In the Work item peek, Status, Priority, Owner and Due are four bordered cells above the other fields: two by two, and four across when the peek is wide enough.
- A use case's own page no longer needs Edit: its name, headline, status, eye, commitment, Where it stands and Archive work as soon as you open it, and an archived use case always shows Restore. A published file is unchanged.
- In a window from 801 to 1000 px wide the top bar's tab row scrolls inside its own box (no scrollbar) and the open tab is brought into view, so the tab you are on, such as Settings, is not clipped.
- In that width range the project name in the top bar shrinks first, before the tabs.
- On the Work items board each column is a lifted card with a line under its header and its count in a small grey pill, a card's border darkens when you point at it, and the full-screen button shows arrows pointing out (in, once full).
- The Sneak peek words box floats at the foot of the peek as a white card with a shadow; the changed lines have a thin rule between them and the new value is in a blue pill.
- In the profile menu, when no name or email has been typed in Settings, the top line is the link to Settings and the Settings entry at the foot is left out, so Settings is not listed twice.
- Work items no longer need Edit: the peek, the row menu, Hand over and the cells' own pickers work as soon as you open the page, and the Export to Excel icon is in the page header. On a row, Enter opens the peek; Right and Left walk across the row's cells and no longer open or close the peek. The Dashboard in View, and a published file, still change nothing.
- When you change a work item's owner, the item stays linked to the person the name matches (an exact match to one person), so renaming or merging the old person later does not put the old name back. Undo puts back the name and the link together, and History shows one Owner line for the change. A name that matches no one is kept as free text with no link.
- Importing from Excel now links an owner to the one live person it names, as an owner edit does, so renaming or merging the old person later does not put the old name back. An owner that names no one stays as text with no link.
- The Not reviewed tile is removed from At a glance, in View and in Edit. The Not reviewed filter, the note in the peek and the days box in Settings, Freshness stay.
- For a person who has not chosen a style, the Dashboard sections are now One card (they were Slim gaps). A style you chose is kept, and a published file with no style word still uses slim gaps.
- Below 1000 px wide the peek of a work item or a milestone fills the window width over the page. At 1000 px and wider it is a side panel as before.
- In Edit, the Dashboard's Current state section now shows its text, as in View. The text is read only there.
- On the Dashboard, an open action, risk or decision that is marked for the client but has no client wording is now listed under its own text (its description, or its decision text), in View, in Edit and in the published file.
- In Dashboard Edit, the hint in the report bar is a blue chip, and a hidden tile has a dashed edge and no grey fill.
- A hover tooltip no longer covers an open menu or panel and is not shown on a button whose menu is open. Esc hides a showing tooltip until the pointer or a key moves on.
- In a published report at 900 px wide, the Work items table gives the Item column more room (the Owner, Due, Priority and Status columns are narrower). At 1400 px nothing changes.
- On the Milestones page, the Legend button now has the information icon before the word Legend.
- In the report's Words box you can now clear a row's client wording: the row then shows its title and stays in its section. The message "The wording can't be blank. Type what the client should read." is gone.
- The brand check on a brand's styling file is harder to get past: an outside address, or a picture in a form clark cannot put in the report, is now caught in more cases.
- The round ? button beside the profile circle in the top bar is gone. Help is still the ? key, Help in the profile menu and the command palette.
- Settings, Personal: Appearance is a radio group (Light / Dark / System) with arrow keys: one Tab stop, and the arrow keys, Home and End move between the choices and pick one.
- In the command palette the active row has a clear 2 px outline, and the kind labels (Page, Project and so on) are shown in capitals; the words themselves are unchanged.
- The ask clark panel's title now reads "ask clark".
- On Work items the bulk selection bar stays under the top bar while the list scrolls.
- In a published report the Work items, Milestones and Use cases tabs share one plain eyebrow line, and each use case in the Use cases tab shows its headline beside its status.
- Settings: each label is at the left with its control beside it, and the control is no longer capped in width.
- The Settings cards are more compact: less padding and a smaller heading.

## What is fixed

- The profile circle in the top bar is now there when no project is open, with the entries that need no project, such as Settings.
- In Help, the last entry of the contents now lights when you scroll to the foot of the page.
- ask clark: the first time you open the panel, the words you have typed are kept and the box can be used while clark checks the connection; only Send waits. A good answer from the check is kept for five minutes, so a second open does not wait again.
- In the Client report menu, opening it with the mouse no longer draws a heavy ring on its first item. Opened by the keys, it still shows where you are.
- A click outside the Work item peek closes it, as Esc does. A click on another row, card or item link moves the peek instead, and a click inside a menu, a list of choices, a dialog or a message leaves it open.
- Print to PDF: the Milestones timeline now prints. It is drawn to fit the page width, with about ten month names when there are many months, and no sideways scroll.
- In the Excel exports, a date before 1900 is written as text (dd-mm-yyyy) instead of a hash-filled cell.
- Closing the Work items peek twice quickly no longer steps Back twice and leaves the page blank: a second close or a pick while the first is still landing does nothing.
- The message for a Settings switch now goes as soon as you leave Settings, in View and in Edit, also after Undo.
- On Work items, Esc with two or more rows or cards picked always clears the selection, and closes the peek, even right after a second pick.
- The first-run name prompt takes the keyboard: the cursor is in the Name box when it opens (unless you are already typing elsewhere), Tab stays inside the prompt, and Esc closes it.
- After Undo the message starts with Undone and names the change (a section move, or a milestone or use case eye change) and the focus goes back to where you were. Archiving an item from its row menu moves the focus to the next row.

## Known limits

- Updating from inside clark is still not switched on. To move from 1.0.2 to 1.0.3, install by hand: rename the old clark folder first, then unzip the download into a fresh empty folder. A plain unzip over the old folder merges old and new files.
- Editing a demo project keeps it: Remove demo data takes away only the demo projects you have not touched.
- In the client workbook only the ID, Original and Shown state are locked, and Priority on the Risks & Issues sheet; the text cells stay editable, by design.
- Sorting is blocked on a protected sheet.
- The Needs from you list on the published page shows the first 100 flagged items; any more are left out.
- A project with no Needs from you section gets one at the end when an item is flagged.
- The Undo on the messages for the Settings switches (Asking, Single-key shortcuts) sets the switch back, but it is not a line in History.
