# clark 0.8.0 (Beta), Mac

Beta means the whole of clark is Beta until version 1.0.

This version includes a change to how clark stores your data. Read this first.

## Read this first: a change to how clark stores your data

- Three changes to the data file format, one step each (from layout 12 to 15). clark makes a safety copy of your data before it changes anything.
  - Step 13: a web page and its Word copy now share one publication number. A Word copy takes its web page's number; every publication you already have keeps its number and its file.
  - Step 14: each project keeps its own 'not reviewed after' number of days (1 to 365). It starts at 14 on every project, so nothing you see changes.
  - Step 15: each publication that was saved with a PDF now records the PDF's file name.
- An older clark refuses the new data file: "This data needs a newer clark. Nothing was changed. Install the latest clark, then try again." Once this version has opened a project file, open it only with this version or a newer one. To go back, restore the safety copy.
- The Install button in Settings will not install this update, because it changes how your data is kept. Download the update and install it by hand.

Theme: look back and set freshness: the Dashboard as it stood on a chosen day, a week picker, a Freshness setting, a People card and one View menu on the filter line.

## What is new

- One View menu on the filter line now holds Layout (Table or Board), Group by, Swimlanes (on the board) and the saved-view actions, instead of separate controls beside the line.
- Settings has a new Freshness card where you set how many days before an item counts as not reviewed. The Dashboard can also show an optional 'not reviewed' tile, which stays off until you turn it on with its eye.
- You can now see the Dashboard as it stood at the end of a chosen day, rebuilt from the change history. It is read only, shows a banner saying so, and has a Back to now link.
- A week picker beside Week ending lists the weeks you have published, newest first, and opens the one you choose read only.
- Settings has a People card: everyone who owns a work item or a milestone, with an email, an organisation and a role. Paste from Excel takes rows of name, email, organisation and role, shows what each row will do (a new person, an update, no change or not added), and adds them in one step with one Undo. A row that cannot be used is named in plain words and nothing is added. The people list is never in a published file.
- A backup now copies each kept publication (its page and its data) once into a folder of its own in the backup folder, and never copies it again. A restore never removes a kept publication.

## What is fixed

- If a publish with Overwrite is refused, a link that was replaced is put back without a gap, and if it cannot be put back the message says so plainly.
- Publishing with Overwrite now refuses a file over 64 MB instead of putting it back cut short.

## Behind the scenes

- A web page and its Word copy can now share one publication number (the Word screens are not yet connected to it).
- The record of each publication now names the PDF file saved with it (nothing new to see on screen).
- Tests and checks only: dark-mode checks for the peek's Latest update and for the status pickers, a few more tests, and the macOS test run now happens at the release gate only.
