# clark 0.7.0 (Beta), Mac

Beta means the whole of clark is Beta until version 1.0.

This version includes a change to how clark stores your data. Read this first.

## Read this first: a change to how clark stores your data

- One change to the data file format, in one step (from layout 11 to 12). Step 12: the rule that stops a saved publication record being changed afterwards now also covers the path to the client's copy, in data files made before this version. clark makes a safety copy of your data before it changes anything.
- An older clark refuses the new data file: "This data needs a newer clark. Nothing was changed. Install the latest clark, then try again." Once this version has opened a project file, open it only with this version or a newer one. To go back, restore the safety copy.
- The Install button in Settings will not install this update, because it changes how your data is kept. Download the update and install it by hand.

Theme: bring more of the prototype's screens into clark (Work items, the progress section, the Dashboard, Settings and Publish), finish the keyboard on the peek and the calendar, and tidy the words a person reads.

## What is new

- With the peek open, Up and Down (when the keyboard is on one of its buttons) show the previous or the next item of the list it was opened from, in the order you see it. It does not wrap at either end, and a line that only a screen reader hears says where you are, for example "A-12, 3 of 14". An arrow that moves onto another row or card takes the peek with it, and Esc puts the keyboard back on the row of the item the peek was showing.
- The peek now slides out when it closes, as it slides in. With Reduce motion on, it just closes.
- The milestone calendar follows the arrow keys the way the prototype does: on a day, Left and Right move one day and Up and Down move one week, into the next or earlier period when you leave this one. Only one day is a Tab stop, and it follows you. Enter on a day with milestones goes to its first milestone, Enter or Space opens it, and Shift+Tab or Esc goes back to the day (with a peek open, Esc closes the peek). Page Up and Page Down move to the earlier or later period.
- Dashboard, use cases, in Edit: each row has a status button (On track, Flag or High risk), and the headline and the name can be changed in place. Each is one change with its own Undo. A "+" in the section header grows to "Add use case" and opens a box (ID, Use case, Status, Headline); an ID that is already used is not accepted, and a use case added this way starts hidden from the client until you turn its eye on. "Add a use case from your project record" lists the use cases that are not on the dashboard and puts the ones you pick on it, in one step with one Undo. A published file has none of these.
- Right-click a work item, or press the menu key, and a menu opens for that item with Draft email to the owner and other shortcuts.
- Hand over: pick several work items, choose Hand over and pick the new owner. All of them change in one step, and one Undo puts them back.
- Supporting documents, in Edit: add a link, change it, leave it out of the published page and add it back, each as one step with its own Undo. Archive takes a document off the list and the published page (it is never deleted), also with Undo, and "Archived (n)" under the list brings one back with Restore. A published file never carries an archived document.
- Settings, Backups: an optional "Copy my backups to" folder (OneDrive is allowed there). Each backup is also copied there as a finished single file, and you can restore a copy from that folder. If the folder cannot be written, clark says so in plain words and your save still works. The live data folder is still refused inside OneDrive.
- Milestones: the eye on a row takes a milestone off the published page, with one Undo. An archived milestone opens read only in the peek with Restore, and each row's second line stays on one line.
- ask clark has a New chat button, so a chat that was stopped by a password or key in an earlier message can start again. It is greyed while an answer is on its way.
- Help is closer to the prototype: a ? button at the top beside the profile circle, a Back button, a search icon and key chips, and each search result marks the word that matched. The ? is in the app only; a published file has none.
- In Publish, with no client folder yet, To client says "No client folder yet. Set it in Settings, Publishing." and the last two words are a link that closes the box and takes you to the Publishing card.
- Settings has an AI card. For now it says "AI suggestions come in a later version." and nothing in it changes anything.
- In Edit, clicking the Summary, This week or Next week text opens the same editor in place, and the text is saved with an Undo.
- The Publish dialog now says which publication this will be, for example "this will be Publication 2", beside when the last one went.
- Duplicate now copies the whole item (status, latest update, owner, dates and the rest), and a copy of a hidden item stays hidden from the client.
- The download now includes the LICENSE and NOTICE.md files.
- A new use case on the Dashboard is hidden from the client until you turn its eye on, and a message says so.
- The first time clark opens with no name saved, a small card at the bottom right asks "What is your name?" with Save and Not now. It does not show again once answered or dismissed.
- In Edit, each use case row on the Dashboard lets you add a next step ("Owner: what it is"), link existing work items, and change where it stands in place.
- A risk or issue can be rated Red, Amber or Green from its status picker whatever its status, Edit's Status cell shows the same live look as View (Overdue, Due soon, Red), and the peek has the same status picker.
- In Edit, the peek of an open action has a Latest update box with a Draft button, every item shows when it was last updated, and a bar warns when an item is overdue or due on a weekend, with buttons to move the date (each move has Undo).
- In Publish the PDF tick now reads Also a PDF, the tile menu says Outline colour, and Help lists all six milestone states.
- Publish now warns 'The client will see this page. Only what is shown in View mode is included.', and the finished dialog closes itself after about a second; the same words stay in the profile menu's note.
- In Edit, the top bar has a project switcher: click the project name to pick another project.
- The report has a cover band showing the project, the week ending and the client.
- Opening a use case shows its next steps with each step's id (a link) and due date, and 'See all N work items' counting every linked item and opening the full list.
- On Work items, Show archived (with a count) lists archived items, read-only, each with a Restore button.
- On a risk or issue, the Priority cell now opens a picker for its impact and likelihood (High, Medium, Low), and the priority follows.
- Work items: each item has a letter badge (A, R, I, D, S or P) in place of the Type column, each group is a card of its own, and a Client-visible column shows an eye for the items your client sees. In Edit the eye turns an item off or on, with a message and Undo. In View it is a mark only, and a published file has no eye column.
- Draft email: for a chase you can pick First chase, Second chase or Firmer chase. It starts on the tone clark would have chosen, and the line beside it says how often the items were chased before, for example "Chased 2 times before". Picking a tone writes a new draft. No tone word goes into the email unless you write it.
- The progress section is closer to the approved design. Overall is three tiles: Project health, Achieved ("of the whole project") and Planned ("by" a date). Below them the bar has a "Planned" label over its mark and a scale from 0% to 100%. The Achieved column of each line has a bar beside its figure.
- Settings: the row of chips is a bar of its own under the top bar. It stays in view as you scroll, never covers a card, and the chip of the card you are reading is marked.
- About you says what it saved, with Undo: "Name saved.", "Email saved.", "Name cleared." or "Name and email saved." Undo puts the earlier words back in the box and the menu.

## What is fixed

- The History footnote and the Excel cover say where your name is set: Settings › Personal › About you. They said Settings › Profile, which is not there. Help says the same.
- Help no longer names a New project menu item, because clark does not have one yet.
- A saved view that the filter line can no longer read stays in the list, with a dashed edge and no count, and says why: "This view cannot be used any more. ... Rename it or archive it." It leaves the filter line and the rows alone. Rename and Archive work on it as on any view. Before, it vanished without a word.
- An empty use case says "Not written yet." in the list and on its page, and "Not written yet. Click to write." where you can type. It said "Nothing written yet."
- A link to a supporting document that only works inside one network or on one computer gets the same message as before: "That link only works inside one network or on one computer, so others can't open it. Use a shared link." That now also covers names ending in localdomain, arpa (such as home.arpa) and router, and the four number ranges set aside for examples and tunnels (192.0.2.x, 198.51.100.x, 203.0.113.x and 192.88.99.x).
- Preview: an address that has already been opened shows a plain page, "This preview is no longer available", and says how to make a new one, not a bare error.
- If publishing over an earlier file loses a race for the publication number, the link to the earlier file that it had replaced is put back, not lost.
- A Word copy for the client is held back, with the same words as the web page, when it carries text you held back from the client. Nothing is written.
- A supporting document of an unknown kind is left out of the published file, so none is published with an empty kind.
- The filter line no longer shows a "Press /" hint: that key opens ask clark, so the hint pointed at the wrong thing.
- Help names the milestone calendar's keys in one plain line.
- A null character hidden in the logo rule of a style is now read as a browser reads it, so the Publish check on the logo rule sees the same text.
- Help says a short mixed value after "api key" or "access key" (such as v2beta3) is not sent, on purpose, even when it is not a key.
- Help says Week ending takes a Friday only, in plainer words.
- Saving your name in Settings no longer waits when clark is slow to read your profile first.
- A failed Word copy to the client folder now says what went wrong once, in one sentence, instead of repeating itself.
- Undoing a hand over of several items now skips only an item whose owner was edited afterwards, and undoes the rest.
- While the Add box is open, the page behind it (the peek, the ask clark panel, Help, the command palette and the buttons on a message) cannot be reached with Tab, a screen reader or a click. The message area still reads out.
- Help lists Freshness among the Work items filters, as the page does.
- Help says how to leave a use case: the Use cases link at the top, Esc, or the Back button of your browser. It said "Back returns to the list", and the page has no such button.
- Help says Delete section is offered for a text section and for the Needs from you section, not only for a text section.
- A date picker opened low in the Work items table now sits above the messages at the bottom left, so its "No date" button can be pressed while a message shows.

## Behind the scenes

- Tests only: the tests that reload the page wait for the new page, and a scan finds any that do not; more tests for the keys on a cell and in a picker, for the empty use case words, and for a link to a closed work item; the colon rule in the plain-words scan; the checks of the CI plan job.
- A release download is built only from the commit that carries its tag.
- The routes for AI suggestions are in the program, switched off, and the Settings card above is the only sign of them.
- Page building waits a bounded time, keeps the old pages if a rebuild fails, and copes with a read-only folder.
- Each publication's page now has its data kept beside it, written once, and a publication can be archived without deleting.
- Tests and tidying only: a test sample for every kind of secret the check knows, a test that Draft email refuses a date written with slashes, and plainer failure messages in the Supporting documents tests.
- Tests only: more tests for the settings chip bar, the About you messages, the progress section's tiles, the chase tone and the Work items table; the Help entries that are still to come are recorded in a file, with no change to what Help says.
- Tests and notes only: one shared growth check in the tests, the notes on which links to documents are turned away now name every ending and number range, and a request for an AI suggestion must say whose it is so that Stop can end it.
