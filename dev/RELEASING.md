# Releasing clark

One page. A release has no workflow: the download is built and attached by hand, so every step below is done before a release is called finished. Each step is one action and says what you should see. Do the steps in order; none of them looks at something made in a later step.

Only a finding marked HIGH holds a release back. Every MEDIUM and LOW gets a Tech Debt card on the clark project board with a Severity label; it may be filed after the cut.

**Why this exists.** v0.3.0 and v0.4.0 were published without a zip: nothing made attaching it a step, and nothing failed when it was missing (found by the check made in pull request 216). v0.1.0 passed on fakes and its `clark.command` failed on a real Mac. So the zip is attached, downloaded back and launched for real before the release is published, and the check at step 20 fails if the zip is missing afterwards.

**Beta.** Every clark release is Beta and a pre-release until version 1.0. The title says so, the Pre-release box is ticked, and the notes say so.

**Freeze.** Only the release branch is frozen: `main` keeps merging while the release is cut and gated, but a new commit on `release-X.Y.Z` restarts the gate (step 3), so the tag always sits on the commit the gate ran on.

**The digest** (the SHA-256 line of the zip) goes in the GitHub release text. It cannot go in the notes file in the repo: that file is already tagged, and a copy of it is inside the zip, so it cannot hold the digest of the zip it is in.

1. **Cut from the release branch.** Branch `release-X.Y.Z` from current `main`, and put the version (`src/clark/__init__.py`) and the hand-check sheet `dev/handchecks/X.Y.Z-sheet.md` in one commit. Before the cut, check that the `ci_scan.py` allow-list pull request and the pull request that adds the tracked `meet clark/` files (the three file names in step 13) are both on `main`; the tag is not made without them. You should see: `git log --oneline -3` shows one version commit on top of main, and `git ls-files "meet clark"` lists the three files.
2. **Write the notes.** Copy the last notes file to `dev/release-notes/X.Y.Z-plain.md` and rewrite it. Keep the first line `# clark X.Y.Z (Beta), Mac` and the line saying the whole of clark is Beta until version 1.0. Use plain words and British English, name no team member and no branch, and back every bullet with code on the tagged commit. You should see: `python3 dev/run_tests.py test_no_real_names` reports every test passed.
3. **Gate green.** Open the release pull request on insyncalan/clark and read its "Tests passed" check, with macOS required on release branches (macOS runs in three shards, and the release branch is the only full macOS run: a push to `main` runs Ubuntu only). If a macOS runner fails to start, re-run it once before calling it a failure. You should see: a green tick on the exact commit that will be tagged. Write down the run number; step 22 needs it.
4. **Tag, and do not publish yet.** Tag `vX.Y.Z` on the exact commit the gate ran on, not on a later one, and push the tag. `package.py --release` refuses unless HEAD is the tagged commit. You should see: `git rev-parse vX.Y.Z^{commit}` prints the gate commit, and the Releases page of insyncalan/clark has no release for it yet.
5. **Check out the tag in an empty folder.** Run `git clone https://github.com/insyncalan/clark clark-release && cd clark-release && git checkout vX.Y.Z`. Never build from a working folder. You should see: `git status` says "HEAD detached at vX.Y.Z" and nothing to commit.
6. **Build the zip.** In that folder run `python3 dev/tools/package.py mac --release --notes dev/release-notes/X.Y.Z-plain.md --out ../zips`. The `meet clark` folder is tracked in git, but it goes in the zip only when you give `--extra-folder "<repo>/meet clark"` on the same command (in the tag checkout the folder is `meet clark`); without the flag the folder is left out of the zip, so the release build must pass it. Only the name `meet clark` ships; files only, no links, 5 MB in all; it lands at the top of the clark folder and is listed in clark-release.json. The zip's README.md is `docs/zip/README.md`, not the root README; every build refuses without it. You should see: "Built the Mac download" and the file `../zips/clark-X.Y.Z-mac.zip`. The two generated pages are not committed (#495): the build makes them from the tagged sources with the pinned esbuild (needs the internet once per machine), builds them twice and refuses the release if the two builds differ by a byte or a page is missing. `package.py` reads the tag's own files: on a clean public tree the zip's Built line and START-HERE.md say that the download holds none of the team's private notes (the exact sentence is the `PUBLIC_BUILD` constant in `package.py`; read it before the cut), and the zip holds nothing the public copy does not. If either says "for the team only", the folder is not a clean tag checkout: do not go on; build again from step 5. (If in doubt, build a second time into another folder and run `shasum -a 256` on both zips; the two lines must be the same.)
7. **Take the digest.** Run `shasum -a 256 ../zips/clark-X.Y.Z-mac.zip`. You should see: one line of 64 letters and digits, then the file name. Copy the 64-character part.
7a. **Sign the zip.** Owner only: the release key lives in the owner's Mac Keychain and nowhere else. Run `python3 dev/tools/sign_release.py sign ../zips/clark-X.Y.Z-mac.zip` and allow access when macOS asks. You should see: "wrote ../zips/clark-X.Y.Z-mac.zip.sig". Attach that `.sig` file beside the zip in step 10. The key is made once with `python3 dev/tools/sign_release.py keygen`, which prints only the public key.
8. **Create the release as a draft.** On github.com/insyncalan/clark, open Releases, from tag `vX.Y.Z`, choose Draft a new release. Title: `clark X.Y.Z (Beta), Mac`. Tick Pre-release. Paste in the notes file. Choose Save draft, not Publish. You should see: the release listed as a Draft and marked Pre-release, its text starting `# clark X.Y.Z (Beta), Mac`.
9. **Put the digest in the release text.** On github.com/insyncalan/clark/releases, edit the draft's text (not the file in the repo) and add at the end: "To check the download is whole, run `shasum -a 256 clark-X.Y.Z-mac.zip` and compare the result with: " followed by the digest, then a new line "This download is not signed yet; check it with the digest above." (Signing is not available yet.) You should see: both lines at the end of the draft's text.
10. **Attach the zip.** On the same draft on github.com/insyncalan/clark/releases, add `../zips/clark-X.Y.Z-mac.zip` as a release file and save the draft. Attach the `.sig` from step 7a beside it ONLY if the owner signed the zip; while the release key in `updates.py` is still the placeholder the in-app updater accepts a zip with no `.sig`, and once a real key is set it refuses one ("unsigned"). The asset check (step 20) does not look for the `.sig`. You should see: the zip listed under Assets, and the `.sig` too if the owner signed it.
11. **Download it back.** Signed in to GitHub, open github.com/insyncalan/clark/releases, open the draft and download the zip under Assets into a new empty folder. Use Chrome, not Safari: Safari may unzip the file and delete the zip, and step 12 would then fail. You should see: `clark-X.Y.Z-mac.zip` in that folder.
12. **Compare the digest.** In that folder run `shasum -a 256 clark-X.Y.Z-mac.zip`. You should see: the same 64 characters as in step 7. If not, do not go on: attach the zip again.
13. **Unzip it the way a person will.** In Finder, move the downloaded `clark-X.Y.Z-mac.zip` into a new empty folder named `clark-unzipped` and double-click it, so Archive Utility unzips it. Do not use the `unzip` command: it drops the download's quarantine mark, and step 15 would then not test what a person meets. (In Terminal, `ditto -x -k clark-X.Y.Z-mac.zip .` inside that folder keeps the mark too.) Then `cd` into `clark-unzipped/clark` (the folder is called `clark`, whatever the version; the zip's own name keeps the version) and run `xattr -p com.apple.quarantine clark.command`. You should see: a line of text, not "No such xattr" (the mark is there), and `ls -A` shows exactly `.app`, `README.md`, `START-HERE.md`, `clark-release.json`, `clark.command`, `docker` and `meet clark` (which holds `clark-getting-started.pdf`, `clark-overview.pdf` and `clark-overview.png`), and NO `src`, `vendor`, `clark` or `system` at the top (the program files are in the hidden `.app` folder; `branding` is the person's own and is never in the download). If the mark is missing, download the zip again with Chrome (step 11) and repeat this step.
13a. **See the name clash a person will meet.** Move the downloaded zip into a second new empty folder, put an empty folder called `clark` beside it, then double-click the zip. You should see: the Mac does not overwrite the old `clark` folder silently (Archive Utility makes a second folder with a number, or asks). If it ever replaces the old folder without asking, do not go on: `START-HERE.md` and the release text must say what to do (rename or move the old `clark` folder first). A plain unzip over an older `clark` folder merges the files, so always rename the old folder first, as `START-HERE.md` says.
14. **Run the doctor with the Mac's own Python.** First quit any clark you already have running: steps 14 to 18 use clark's normal port, 8766. In that folder run `PATH=/usr/bin:/bin bash clark.command --check --data ../clark-check-data --port 8766` (the doctor, run from the hidden `.app` folder). You should see: no "To fix" line and the last line "Everything clark needs is ready." If anything needs fixing, do not go on.
15. **Launch it the way a person will: double-click it in Finder.** In Finder, open the `clark` folder you unzipped from the downloaded zip and double-click `clark.command`. Do not start it from Terminal for this step: the v0.1.0 download failed on a double-click, and a file downloaded by a browser is treated differently by macOS when it is double-clicked. **The dialog is expected:** the download is not signed or notarised, so the first double-click shows a dialog that says `clark.command` was not opened because Apple could not verify it is free of malware, with only "Move to Trash" and "Done": that dialog is not a failure (on an employer-managed Mac, Open Anyway may also ask for an administrator's password). Choose Done, never Move to Trash, then do exactly what `START-HERE.md` step 2 under "Without Docker" tells a person to do (System Settings, then Privacy & Security, then Open Anyway beside `clark.command`), and write down what macOS said. You should see: a Terminal window saying "Starting clark...", then a clark window opens in Chrome showing the clark page. If you see "Permission denied", "Press any key", a refusal that `START-HERE.md` does not get past, or no window, do not go on.
16. **Ask clark if it is well.** Run `curl -s http://127.0.0.1:8766/health`. You should see: a line starting `{"ok": true`.
17. **Double-click it a second time.** Double-click the same `clark.command` in Finder again. You should see: "It is already running. Opening its window." and a window opens; no second clark starts.
18. **Close every clark window.** You should see: within three minutes `curl -s http://127.0.0.1:8766/health` prints nothing, because clark stops by itself two minutes after its last window closes.
19. **Publish the release.** Only if steps 11 to 18 all passed: if any failed, leave the draft, do not publish, and tell the Head. Open the draft on github.com/insyncalan/clark/releases, check Pre-release is still ticked, and choose Publish release. This is the last step before the board and the log. You should see: the release page with a Pre-release badge, the title `clark X.Y.Z (Beta), Mac` and the zip under Assets.
20. **Run the check on the live release.** Run `python3 dev/tools/check_release_assets.py vX.Y.Z`. The check reads insyncalan/clark through `gh` (signed in: `gh auth login`); if the releases are ever kept in another repository, add `--repo owner/name`. It looks at the zip, the Pre-release box, "(Beta)" in the title, Beta in the release text, that the SHA-256 in the release text is the zip's own digest as GitHub reports it, that the zip was attached before the release was published, and, once the release key in `updates.py` is a real key, that `clark-X.Y.Z-mac.zip.sig` is attached and verifies over the zip with that key (a line saying the release has no `.sig`, or that it does not verify, means the owner repeats step 7a and replaces the file; run with no tag, it asks this only of releases published after `FIRST_SIGNED` in the tool, the time the key went live, and a tag you name is always asked). You should see: "Every published release has its download attached." If you see a line starting with the tag, or "No published release named", the release is not finished: follow that line. A line starting "Note:" means GitHub gave no digest for the zip, so compare `shasum -a 256` with the release text yourself.
21. **Board.** Open the clark project board and filter Release = X.Y.Z. You should see: every card in State Shipped. Move any card that did not make it to the next release.
22. **Release row.** Post the row on issue #1 of the team's plan repository (the private one the board keeper already works in; its name is not written in this public file), as a new comment: tag and commit, publish time, the gate run number from step 3, contents, verdicts, what is not in it, Tech Debt carried. `dev/HEAD-LOG.md` is not in this repository any more (#463); do not add it back. You should see: the new comment at the bottom of issue #1 of the plan repository, with the tag in its first words.
23. **Hand over the hand-check sheet.** Give `dev/handchecks/X.Y.Z-sheet.md` to the person who checks the screens. You should see: them confirm they have it. It does not hold the release up.
24. **Install it on the Head's own Mac.** Rename any old `clark` folder first. Unzip the download into a fresh empty folder, `cd` into `clark` and run `bash clark.command --check`, then start clark. Leave `system/` and `~/Library/Application Support/clark` untouched. You should see: the doctor's last line "Everything clark needs is ready.", `curl -s http://127.0.0.1:8766/health` starting `{"ok": true`, and X.Y.Z as the version in Settings.

## Who does what

| Role | What they do | Steps |
|------|--------------|-------|
| The Head | Leads the team; tags, creates the draft and publishes the release, installs it on their own Mac | 4, 8, 9, 10, 19, 24 |
| The owner | Signs the zip (the release key is in the owner's Mac Keychain) | 7a |
| The builder | Builds the zip and takes its digest | 5, 6, 7 |
| The release-branch owner | Builds the release branch and writes the notes | 1, 2 |
| The board keeper | Keeps the board and the release row on issue #1 of the plan repository, and hands over the hand-check sheet | 21, 22, 23 |
| Whoever verifies | Reads the gate, downloads the zip, launches it for real and runs the asset check | 3, 11, 12, 13, 14, 15, 16, 17, 18, 20 |
