## 0. What the built #39 changes about the draft
- `publish()` exists but **no route and no button** (its Q3). `/api/publish` is not in `POST_ROUTES`, so #43 builds the route: the readiness draft's "adds a flag" cannot hold. See Q4.
- `publish(store, code, folder, *, overwrite, now, branding, log)` writes Local, reads it back and calls `log(done, week_ending)` once. **`Store.log_publication` does not exist** (#39's Q2 "not now"), and `publish()` has no file-name argument: both are needed here.
- `file_name()` is `platform.safe_name(f"{code}-report-{week_ending or date}.html", folder)`. `safe_name` cuts from the end, so on a very deep folder the date is cut first (`PUB-report-20.html`, fixture `deep-folder-shortens-the-name`) and weeks would collide. Rare; noted, not fixed.

## 1. What To client does
1. **The dialog.** Publish opens (a button on the report bar until #64). **Local** is ticked and disabled. **To client** is unticked every time it opens, never remembered (not even in `localStorage`). With no saved client folder it is disabled and says "No client folder yet. Set it in Settings." With one, it names the folder. Ticking it changes the button to "Publish and send to the client" and shows "The client will see this page. Only what is shown in View mode is included." (#437, the prototype's words). No Word tick (Word is #48).
2. **Press Publish.** The button is disabled while it works; the server handles one publish at a time. The request is `POST /api/publish {project, to_client, on_clash?, new_name?}` and nothing else. It never names a folder or file: the client folder is read from `projects.publish_client`. `to_client` must be exactly `true` or `false`.
3. **Before anything is written** (no dialogs, no files): the saved folder is checked again (§3, it may have gone since Settings), the file is built once (`select` and `render`), its name is `publish.file_name(code, week_ending, today, client_folder)` (the standard name, not the Local name), and the folder's names are read. A taken name (letter case ignored, as macOS and OneDrive do) with different bytes answers `{ok:false, clash:true, name, numbered, can_overwrite}` and nothing is written. The page shows creaite's dialog: "A file with that name is already in the client folder", **Add a number** (default, "saves as “PUB-report-2026-10-23 (2).html”"), **Rename it** (a field), **Overwrite the existing file** (hidden if a folder has the name), **Cancel**. The choice comes back as `on_clash` and the server starts again from here. A rename that is also taken asks again. Identical bytes: nothing to copy, said so.
4. **Local first.** The system's Save dialog (`platform.choose_save_file`, D-10) is #39's half. Cancelling it cancels everything: nothing is written. Then `platform.write_file`, read-back, SHA-256.
5. **The copy.** The same bytes go into the client folder with `platform.write_file` (a temporary `.part` file beside it, then replaced; retries for OneDrive locks), are read back, and their SHA-256 must equal the Local file's. A copy that differs is removed if this publish made it; an Overwrite cannot be undone, so the message says to publish again. Overwrite makes **no backup in the client folder**, because OneDrive would upload it to the client.
6. **The log.** One `publications` row per publish (§3). `client_path` is set only for a verified copy. A Local publish whose copy failed is still logged, with `client_path` empty.
7. **What the user sees** (wording in the fixture's `messages`): "Published. Saved locally, and copied to the client folder as “X”. OneDrive uploads it from there; clark can't see when that finishes." It says copied, not sent, because clark holds no Microsoft sign-in and has no network code (NFR-2, ARCHITECTURE.md). The report bar reads "Published DD-MM-YYYY to the client" or "locally" from the latest row.
8. **Failures.** Folder missing, not writable or not allowed (checked in step 3): nothing is written, Local included, the dialog stays open with the message and the user can untick To client (Q3). A failure after Local is written (copy refused, locked, differs): Local stays, the message starts "Saved locally, but not copied to the client folder", and nothing is added to the client folder.
9. **Never by itself.** Only this route writes into the client folder, and only with `to_client: true`. Import, `/api/change`, undo, the Excel routes, ask clark and Settings cannot (ARCHITECTURE.md, "never by itself, on a schedule, from ask clark or from an import").

## 2. What is checked before copying, and the test that proves it
Under #24 there is one output and no client checks are copied. What goes in is decided **before the file is made** (#39's `select()`); the copy is a byte copy of that file. The Head ruled on Q5 (review of the pure parts): the run-time check IS on. `check_copy` runs on the bytes before the write and again on the copy read back, with `markers` (text that must be absent) a required argument and no switch to turn it off. A new name is linked into place (`platform.move_unless_exists`), so a file that appears after the listing is refused, never overwritten. An Overwrite needs `"confirmed": true` in the request and keeps the old bytes in memory to put back if the copy fails its check. Names and folders are compared ignoring case and Unicode form. Test names are #39's, in `tests/test_publish.py`.

| Check | Where it is enforced | Test that proves it (reused, not rewritten) | #43 adds |
|---|---|---|---|
| Only rows with the client flag on, not hidden, not archived | `select()` GATES, `report_hidden` | `test_flag_off_rows_absent_from_bytes`, `test_report_hidden_rows_absent`, `test_archived_absent_even_if_data_for_sent_it`, `test_every_marker_absent_in_four_spellings` | the same marker search, with #39's `spellings()` and `publish-plant.json`, on **bytes read back from the client folder** |
| No internal note, Movement text or source | `PUBLISH_FIELDS` allow-list | `test_internal_note_movement_source_never_copied`, `test_project_folders_absent`, `test_no_forbidden_keys_and_only_kept_ids` | same, on the copy (the client folder path itself must not be in the copy) |
| No Sensitive or other excluded label | `select()` label rules | `test_sensitive_and_any_exclude_label_rows_absent` | same, on the copy |
| Client words (Slipped "Expected later", Overdue "Late"; `client_message` optional) | `render()` | `test_milestone_state_words_embedded` | nothing. Gap for #39: no test asserts that a kept row's `client_message` shows instead of its own text |
| No outside address | `check_brand`, CSP, `clean_html` | `test_no_outside_address_in_attributes_css_or_srcs`, `test_font_or_import_url_in_brand_is_refused`, `test_C_no_request_leaves_the_file` | the address scan on the copy's bytes (make #39's scan an importable helper) |

| Nothing else writes into the client folder; never by itself | route table, server | #33's every-route-needs-a-token test | the tripwire and source tests in §5 |

## 3. Data and settings
- **No schema change.** `projects.publish_client` (TEXT) holds the **absolute path of a folder on this computer that OneDrive syncs**. The column comment in `schema.sql` (line 21) and `data-model.md` (line 38) say "SharePoint folder": a comment-only fix (§6). `publications` already has `client_path`.
- **`publications` row:** `project`, `at`, `week_ending`, `local_path`, `client_path`, `word` 0, `file_sha256`, `checks` `'not needed'` (Q2), `by_user` (Settings › Profile name). One row per publish, written after both writes, by the new `Store.log_publication(...)` (guarded #31 edit: Head to rule), which also sets `projects.publish_local`. The wrapper calls `publish(..., log=None)` and logs itself once with both paths. `publish()` stays as built, except for a `name=` argument for the Save dialog's name and a `build()` split out of it (tests unchanged).
- **How it is set.** `POST /api/client-folder {project, action: "choose"|"clear"}`. The server runs `platform.choose_folder("Choose the folder OneDrive syncs for the client", start=)`, starting at the saved folder, else the first of `platform.onedrive_roots()`. Cancelled: nothing changes, no message. Otherwise `check_client_folder`; a refusal changes nothing and says why. Saved with `Step.update("projects", code, {"publish_client": path})` (via `dashboard`), so it is in history and can be undone. The route **never writes into the folder** (it asks `os.access`, it creates no test file).
- **`check_client_folder(path, ...)`, in this order** (pure; the disk facts come in as arguments): none saved; inside or equal to `platform.data_dir()` (compare real paths by parts, so `clark-old` is not inside `clark`); contains the data dir; equals the project's `publish_local`; missing; not a folder; not writable. Then it passes. **Outside every OneDrive root it still passes, with a warning** (OneDrive roots are suggestions only; `platform.inside_onedrive`). Settings help text: "This must be a folder OneDrive syncs to the client's SharePoint."
- **Checked again at every publish** (step 3), because OneDrive can be signed out or the folder moved. The prototype's Settings field takes a SharePoint web address (`views.js:655`, `type=url`); the page replaces it with the folder name, a Choose folder button and Clear. Nothing in the published file names the folder (`publish_*` columns are never copied, #39).

## 7. Open questions
1. **The owner: a file of that name is already in the client folder.** *Recommend* Add a number (default), Rename, Overwrite, Cancel, for the client copy only, and the client file always has the standard name `{CODE}-report-{date}.html` (not the Local name, which the user may have typed freely). A second publish on the same day is the usual cause, so Overwrite is one click. Default: that.
2. **The Head: `publications.checks`.** NOT NULL and only `'passed'` or `'not needed'`, and the checks are gone. *Recommend* `'not needed'` for Local and To client, leave `schema.sql`, drop the column in a later schema version. Default: that.
3. **The owner: the client folder is missing or locked when To client is ticked.** *Recommend* stop before writing anything (Local too), so nothing is half done and the user can untick and publish locally. The other choice is to publish Local and report the failed copy. Default: stop.
4. **Head: who builds what.** Nobody owns the Local half of `/api/publish` (Save dialog, `name=`), `Store.log_publication` or the Settings folder field. *Recommend* #43 builds the route end to end (Local and client) and the log method, with Review Light plus the Head's ruling on the one guarded `store.py` edit; the Settings field goes into #45. Default: that.
5. **The owner or the Head: a check on the copy at run time?** *Recommend* no: #24 chose one output with tests, and the copy is the same bytes. The cheap alternative is to parse the file's `clark-data` before copying and refuse on a forbidden key. Default: no.
